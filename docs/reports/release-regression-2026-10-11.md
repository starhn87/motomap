React 검토에서는 기존 운영 게이트 이후의 lazy 로딩을 유지하고, 준비 상태/단계만 effect
의존성으로 사용하며 타이머 취소·최초 실행 1회 숨김을 확인했다. 개인 화면·원본 xcresult는
저장소 밖 private 경로에만 보관한다. 프리 웜업·성능 측정·계정 변경·푸시·공개 배포는 하지 않았다.

최종 사용자 확인: 스플래시 전환이 정상 동작한다고 확인했다. 첫 지도 렌더 완료 기반 전환은
출시 후 개선 백로그(PERF-007)로 명시적으로 미뤘다. 현재 릴리스의 타일 렌더 완료 대기나
프리 웜업이 구현된 것으로 표시하지 않는다.

## 출시 준비 후속 — 길안내 장애 반복 호출

NAV-009/PROVIDER-001의 일부를 보완했다. 확인된 설정 오류는 재진입·옵션 변경·안내 시작에서도
초기화/네이티브 경로 요청을 반복하지 않으며 UI에 불가능한 재시도 버튼을 표시하지 않는다.
경유지 축소와 코스 출발지 폴백은 해당 도로 단절 코드에만 적용한다. 기존 경유지 폴백·이륜차
경로와 20초 제한·늦은 응답 무시는 유지한다.

- `npx tsc --noEmit`: 통과. 자동 테스트 **94개 통과·실패 0**(초기화 6개, 코드 분류/폴백 3개,
  실제 훅 대역 5개 추가). 모듈 import 대역 오류로 인한 초기 실패는 러너 수정 후 재통과했다.
- SDK·네트워크·React 스케줄러 대역 기반이다. 설치한 내부 앱은 `b6a1501`까지이며 이 후속
  소스는 새로 빌드·설치하지 않았다. 수정본 실기기 장애 주입·TestFlight 성공으로 표시하지 않는다.
- 네이티브/API 계약·의존성·운영 설정·사용자 데이터는 바꾸지 않았다. 원격 공급자 설정 오류를
  만들기 위해 production 키·상품을 끄지 않는다. Git 푸시·빌드·OTA·공개 배포는 하지 않았다.

## 승인된 DB 정비·날씨/유가 실패 처리 후속

사용자 승인으로 운영 DB 정비 2건을 적용했다. 상세 적용 버전·권한·보존 검증은
[DB 정비 보고서](relaunch-database-security-2026-10-11.md)를 따른다. 리뷰 16개·즐겨찾기
18개·장소 방문 39개의 전후 전체 행 체크섬이 일치했다. 실제 삭제 RPC는 호출하지 않았고
계정 삭제 실동작·백업/PITR 사본 보존기간은 아직 확인하지 않았다. 자동 작업 3개는 정지다.

날씨·유가는 시간 제한과 응답 검증, 최초 실패/이전 데이터 표시·수동 재시도를 추가했다.
실제 설치된 FunctionsClient의 HTTP 처리·AbortController와 앱 API/쿼리 모듈을 대역으로
검사했다. WeatherFab의 실제 반환 트리·핸들러, useGasLayer의 실제 상태/effect를 연결해
고정 버튼 공간·이전 예보·즉시 터치 해제·동일 범위 refetch·중복 호출 방지를 확인했다.

탐색 대조에서 기온 결측 `tmp:null`은 미래 예보의 기존 Edge 계약임을 확인했다. 현재 기온
결측은 실패하되 미래 기온 칸만 생략한다. 해당 칸의 강수·낙뢰는 원래 6/12시간 계산에 남기고,
사용하지 않는 13~24번째 기온 결측으로 현재 예보를 버리지 않는 회귀 검사를 추가했다.

- verifier 최종 검사: 타입 검사·자동 테스트 **114개 통과, 실패/건너뜀 0**·릴리스 검사
  (app 1.2.8, native/API 계약 1)·diff 검사 통과. Edge Deno lint/check 22개 파일도 통과했다.
  앱 전용 lint/build 스크립트는 없으며 Metro export·네이티브 빌드는 수행하지 않았다.
- 구현 변경은 MAP-039/PROVIDER-001에 기록했다. 미래 예보 부분 결측, 정상 가격 0건,
  Edge 401/403과 공급자 설정 오류의 구분을 유지한다. 대역 검사를 실기기 렌더·Gesture
  검증이나 공급자 장애 대응 전체 완료로 해석하지 않는다.
- 설치된 내부 앱은 `b6a1501`까지다. 새 길안내·날씨/유가 수정본은 아직 빌드·설치하지 않았다.
  수정본 실기기 장애 주입, 유가 부분 타일 실패 안내, 경로 날씨/특보/대기질 실패,
  SDK 지도 실패 감시·원격 플래그·Sentry fingerprint 검증은 남는다.
- 운영 DB의 승인된 2건 외에 추가 마이그레이션·공급자 설정·자동 작업·공개 상태는 변경하지
  않았다. 푸시·빌드·OTA·웹 배포·알림은 하지 않았고 성능 측정/프리 웜업은 계속 보류한다.

## 최신 내부 빌드·실기기 회귀 (TestFlight 업로드 승인 후)

사용자가 최신 내부 빌드·실기기 검증과 **검증 통과 후 TestFlight 업로드**를 승인했다.
Git 푸시·App Store 심사·판매 재개·공개 상태 active·OTA·사용자 재개 알림은 승인 범위가 아니다.

- 앱 소스 기준: `08b21d3`(최신 길안내·날씨/유가 실패 처리와 1.2.8 공지 포함).
  기존 스플래시·Expo 57/RN 0.86.3 네이티브 조합을 유지했다. 내부 EAS image만 로컬과 같은
  Xcode 27.0 안정판(27A266a)으로 고정했고 production 프로필은 바꾸지 않았다.
- private 스냅샷에서 Release 서명 빌드·기존 앱 위 설치를 통과했다. 앱/runtime 1.2.8,
  내부 채널 `internal-testflight`와 codesign을 검사했다. 로컬 개발 서명의 build 1은
  TestFlight 배포 번호가 아니다. 원본 저장소의 unrelated 로컬 파일과 사용자 데이터는 지웠거나
  덮어쓰지 않았다. 초기 작업 디렉터리 오류로 시작한 이전 소스 빌드는 중단했고 최신 파일의
  동일성을 확인한 뒤 새 빌드를 수행했다. 그 중단을 앱 컴파일 결함으로 집계하지 않는다.
- 같은 설치본의 XCTest 기능 smoke **5개 통과, 실패 0**: 사진 3장 이동·핀치·확대 중 pan,
  날씨 열기/닫기, 내 정보·설정 읽기, 커스텀 장소 콜드/웜 링크, HTTPS 콜드/웜 링크.
- 추가 등록 장소 경로 미리보기 smoke **1개 통과**: 실제 경로 옵션 4개·거리·예상 시간과
  안내 시작 버튼을 확인한 뒤 앱을 재실행해 지도로 복귀했다. 첫 검사는 옵션을 StaticText로만
  찾는 러너 오류로 실패했다. 실제 캡처와 접근성 계층의 Other를 확인해 러너를 수정·재빌드했다.
  안내 시작/종료는 누르지 않았다. 실제 주행·안내 정상 종료·방문 기록 생성 검증은 아니다.
- 공개 테스트 좌표에서 **현재 앱 API 모듈+실제 FunctionsClient**를 실행했다. 세션을 저장하지
  않는 public 키로 유가 주변 52개·상세 가격 3개와 날씨 12개 시간 예보의 응답 계약을 통과했다.
  운영 공급자를 끄거나 실제 이용자 좌표를 테스트 입력으로 쓰지 않았다. 이 API 검사는
  유가 지도/카드의 모든 실기기 상태나 장애 주입 검증을 대신하지 않는다.
- DB 재대조: 리뷰 16개·장소 방문 39개의 전체 행 체크섬과 기존 즐겨찾기 18개의 체크섬은
  정비 전과 동일하다. 즐겨찾기 총 20개 중 추가 2개는 이번 설치·smoke 전 생성됐다. 추가분을
  데이터 손상으로 오인하지 않는다. 장소 운영시간 캐시 771개는 수가 같지만 전체 체크섬은
  달라졌다. 이를 사용자 기록의 손실이나 캐시 내용 불변의 근거로 삼지 않는다.
  계정·리뷰·즐겨찾기·방문 기록을 변경하는 테스트는 실행하지 않았다.
- 클라우드 입력은 커밋된 소스의 clean clone으로 분리했다. 아카이브 623개 파일에 앱 설정,
  lockfile·KNSDK podspec/plugin·Naver patch·원본 스플래시가 포함됐고, generated native·
  node_modules·인증서·실제 .env·untracked 에이전트 파일은 제외했다. `.env.example`만 포함했다.
  EAS production 변수의 존재와 필요한 client 값 일치를 확인했으며 값·키·로그·기기 원본
  xcresult와 캡처는 저장소 밖 private 경로에 둔다.
- EAS 내부 빌드 요청: `fd4e959b-47fc-4428-abf7-203cf8fee415`, 앱 1.2.8 / build 36,
  profile/channel `internal-testflight`, 소스 커밋 `08b21d3`. 당시 클라우드 빌드는 진행 중이며
  TestFlight 제출·Apple 처리·설치 가능 확인은 아직 완료로 표시하지 않는다.
- 로그인한 ASC에서 기존 `internal`은 본인 1명의 내부 그룹이고 외부 그룹이 없음을 확인했다.
  새 계정·테스터·외부 그룹이나 공개 링크를 만들지 않는다. 최종 성공 산출물의 build ID를
  지정해 이 내부 그룹에만 제출하고 후속 결과를 기록한다.

현재 검증은 내부 TestFlight 후보 업로드를 위한 기본 회귀다. 전체 외부 장애 주입·실제 주행·
제공자별 OAuth·알림/탈퇴·App Store 심사 접근·개인정보 최종 대조가 끝난 것으로 표시하지 않는다.
CPU/메모리 측정·최적화와 첫 지도 렌더 기반 스플래시/PERF-007은 계속 보류다.

## 네이버 검색·집/회사 설정 후속 내부 검증

`a1f6dea`의 네이버 검색 보완과 `be6c72c`의 설정 확인창은 위 TestFlight 1.2.8 (36) 이후 변경이다.

- 동일 Xcode 27·Expo 57 네이티브 조합의 개발 서명 Release를 기존 앱 위에 설치했다.
  로컬 build 1 / runtime 1.2.8 / internal-testflight이며 TestFlight (36)이 갱신된 것이 아니다.
  제품 분석 키는 검증 빌드에서만 제외했고 앱 source의 분석 설정은 바꾸지 않았다.
- 초기 메뉴 선택자에는 장식 아이콘이 앞에 붙었고 입력 후 placeholder가 요소 이름에서 사라져
  임시 러너를 실제 접근성 트리에 맞췄다. 화면에 확인창이 있지만 카드가 자식 버튼을 묶는 문제는
  바깥/카드의 접근성 그룹화 해제로 보완했다. UI 자동화의 첫 탭 선점은 내부 목록만 바꿔 해결되지
  않았고 프로필 부모 ScrollView의 탭 정책도 보완했다. 직접 터치는 기존 설치본에서도 정상이라는
  운영자 확인과 자동화 관찰을 구분한다.
- 최종 XCTest **3개 통과, 실패 0 (88.6초)**: 기존 로그인 상태, 집, 회사. 집/회사 각각 재탭 없이
  확인창 표시, 취소·바깥 탭 후 목록/검색어 유지, 설정, 프로세스 재시작 뒤 영속 저장을 확인했다.
  임시 러너의 2초 안정화 대기는 앱 코드의 지연이 아니며 두 번째 탭 폴백은 없다.
- 테스트용 공개 장소 저장 뒤 로컬 `my-places` 키만 원래 값으로 복원했다. 다른 현재 키는
  유지하고 앱 재실행 뒤 원본 값의 정확한 일치를 확인했다. 개인정보·키·캡처는 커밋하지 않는다.
  서버 사용자 기록 쓰기·계정 재인증·탈퇴·Android 뒤로가기 검증은 실행하지 않았다.
- 타입·자동 테스트 136개·릴리스·diff 검사를 통과했다. 수정된 iOS 확인창 화면도 비공개
  캡처로 확인했으며 네이티브/runtime/API 계약은 그대로다.

### 심사 제출 전 남은 핵심 게이트

1. 최신 소스의 별도 production 배포 서명 빌드와 최종 확인이 필요하다. 현재 TestFlight (36)은
   두 기능을 포함하지 않으며 내부 채널 바이너리를 그대로 App Store에 선택하지 않는다.
2. 이번 읽기 전용 조회에서도 공개 `/service-status`는 `preparing`, 최소 버전 1.2.8이었다.
   현재 production은 로그인 전에 차단돼 심사 계정만 제공해도 기능을 검증할 수 없다.
   승인된 심사 접근을 준비·검증해야 하며 공개 active로 임의 전환하지 않는다.
3. 관찰한 공개 `/privacy`는 서버 렌더 HTTP 200이지만 로컬의 대표자·API HUB 고지를 포함하지
   않았다. 공개 법률 페이지·앱·ASC 고지의 최신 내용과 시행일/고지 절차를 최종 대조·반영한다.
   이 관찰만으로 오래된 배포·캐시 중 원인을 확정하거나 법률 검토 완료로 표시하지 않는다.

전체 공급자 장애·알림/탈퇴 등 기존 미검증 범위는 보존한다. CPU·메모리 전체 측정·프리 웜업은
출시 후 보류 항목이며 제출 조건으로 다시 추가하지 않는다. Git 푸시·OTA·웹 배포·TestFlight
업로드·심사 제출·판매 재개·운영 재개 알림은 이번 후속에서 실행하지 않았다.

## 심사 접근 간소화와 검증 범위 정정

2026-10-11 운영자는 별도 심사 접근 코드 대신 고지·운영 준비 후 승인된 정상 진입을 먼저
열고 심사하는 순서를 선택했다(OPS-007). 작성 중이던 미커밋 접근 코드·서버 endpoint·테스트를
제거했으며 원격 설정이나 앱 동작은 변경하지 않았다. 기존 준비 게이트로 그대로 돌아간다.

앞서 남은 항목을 ‘최종 기능 검증’으로 묶어 안내한 것은 이미 끝낸 검사와 혼동될 수 있었다.
최신 내부 설치본의 지도·검색·상세·사진·날씨·설정·콜드/웜 링크·집/회사 확인창 검사와 사용자
로그인·길안내 정상 확인은 완료 기록으로 유지한다. 전체 기능 검사를 다시 수행하지 않는다.
새 production 빌드에서는 서명·채널·버전·설치·시작·정상 서비스 진입만 짧게 확인한다.
기존의 미검증 장애 주입·탈퇴 등은 완료로 표시하지 않되 모든 심화 검증을 새 출시 선행 작업으로
임의 추가하지 않는다. 발견된 결함이나 실제 출시 위험은 근거와 함께 따로 보고한다.

고지·약관 동기화와 production 빌드·심사 제출은 기능 검증과 별개로 남아 있다. 개정 시행일은
실제 재개일에 맞추되 아직 날짜를 정하지 않았다. 푸시·배포·빌드·심사 제출은 실행하지 않았다.
