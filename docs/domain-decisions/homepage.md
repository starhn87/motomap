# 홈페이지 디자인

## WEB-001 — 감성적인 첫 화면과 단정한 제품 소개를 분리하는 시안

- 날짜: 2026-10-13
- 상태: 대체됨(WEB-002 — 사용자 거절로 시안 롤백)
- 관련 구현: 시안 커밋 `cb7ade2`의 `website/prototypes/home-renewal/` (롤백됨)

### 배경

같은 라이딩 배경 위에 큰 앱 캡처와 제목을 계속 겹치는 구성에서 정보가 경쟁했다.
운영자는 깔끔하고 심플한 애니메이션 리뉴얼 제안에 동의하고 첫 화면·발견 섹션 시안을 요청했다.

### 시안의 결정

1. 첫 화면의 라이딩 사진과 바이크 중심 분위기는 유지하고 제목·설명·다운로드만 남긴다.
2. 발견은 차콜 배경으로 분리한다. 기존 선호처럼 데스크탑·모바일 모두 큰 실제 앱 화면을
   텍스트 위 중앙에 두고 지도/AI 캡처를 미리보기로 전환한다. 없는 기능·수치·후기를 만들지 않는다.
3. 짧은 등장·사진의 소폭 확대만 사용하고 모션 감소 설정과 JS 없는 콘텐츠 접근을 지원한다.
4. 시안은 자연 스크롤이다. 기존 홈페이지의 단계 잠금·제스처 처리 시행착오를 잊고 조용히
   대체하지 않는다. 운영에 합칠 때 변경 범위와 기존 스크롤 대체를 별도 확인한다.
5. 운영 public 디렉터리·Worker·약관·공유·AASA·상태 endpoint는 수정하지 않는다.
   시안은 loopback 전용 허용 목록 서버에서 확인하며 푸시·배포하지 않는다.

### 재검토 조건

시안 승인 뒤 길안내·내 바이크 소개로 확장하는 안이었으나 WEB-002로 중단했다.
실제 라이딩 영상은 촬영본이 생겼을 때 검토한다. 시안과 실서비스 구현을 같은 상태로 표시하지 않는다.

## WEB-002 — 첫 화면·발견 시안을 거절하고 롤백한다

- 날짜: 2026-10-14
- 상태: 활성
- 대체 대상: WEB-001 시안과 후속 확장

운영자가 시안을 확인한 뒤 "별로다. 롤백해."라고 요청했다. 구체적인 불만의 이유는
확인되지 않았으므로 색상·스크롤·구성 중 무엇이 문제였는지 추정해 기록하지 않는다.

`cb7ade2`에서 추가한 시안 코드·서버·내보내기 도구를 제거하고 결정 이력만 남긴다.
시안은 푸시·배포하지 않았으므로 운영 홈페이지와 앱은 변경할 필요가 없다.
별도 요청 없이 같은 시안을 다시 적용하거나 길안내·내 바이크 섹션으로 확장하지 않는다.

## WEB-003 — 밝은 지도 톤(Paper Map)으로 홈페이지를 전면 교체한다

- 날짜: 2026-10-14
- 상태: 활성
- 관련 구현: `website/public/index.html`, `website/public/home.css`, `website/public/site.js`

### 배경

운영자가 "심플하고 깔끔하면서 간지 있게" 전면 리뉴얼을 요청했다. 서로 다른 세 방향
(A 밝은 지도 톤, B 검정+테일라이트 레드, C 중앙선 노랑 포스터)을 비교한 뒤 A를 선택했다.
WEB-001에서 거절된 구성(사진 첫 화면+차콜 발견 섹션+중앙 큰 캡처)은 의도적으로 피했다.

### 결정

1. 미색 종이(`#f3f1ec`)+잉크 블랙 단색. 앱 UI(흰 화면·검정 버튼)와 톤을 맞추고, 강조색은 두지 않는다.
   앱 브랜드가 검정이어도 사이트 배경까지 검정일 필요는 없다는 운영자 확인을 받았다.
2. 첫 화면은 좌측 대형 제목·우측 지도 캡처뿐이다. 등고선(동심원) 배경은 "눈이 아프다"는 피드백으로,
   얇은 경로선은 "도로로 확실히 읽히지 않으면 없애라"는 피드백으로, 캡처 옆 "카페 · 뷰포인트" 칩은
   캡처 속 카테고리 칩과 정보가 겹치고 지도 위치와 연결되지 않아 제거했다. 하단 기능 목차·`iPhone` 메타 줄과
   라이딩 사진 띠는 운영자 요청으로 제거했다. 장식은 의미가 분명할 때만 다시 넣는다.
3. 기능 5장은 좌측 글 + 우측 sticky 폰. 화면 중앙의 챕터에 맞춰 캡처를 교체하고, 나머지 챕터는
   큰 제목만 흐리게(opacity 0.5, 큰 글자 대비 3:1 유지) 하고 본문 대비는 유지한다.
   모바일은 sticky 없이 챕터마다 캡처를 인라인으로 둔다. 캡처 설명(alt)은 챕터 안 인라인 캡처에만 두고
   데스크톱 sticky 무대는 `aria-hidden`으로 처리한다. 데스크톱에서도 인라인 캡처는 `display:none`이 아니라
   시각적으로만 숨겨(같은 URL이라 추가 다운로드 없음) 스크린리더가 챕터 순서대로 한 번씩 읽게 한다.
   캡처 프레임(둥근 모서리·패딩)은 반드시 `div.phone`이 `img`를 감싸게 한다. `img`에 직접 주면
   이미지 모서리가 프레임 밖으로 각지게 튀어나온다(모바일에서 발견).
   첫 화면(지도)과 챕터 1이 같은 캡처를 반복하지 않게 챕터 1은 장소 목록이 보이는 검색 화면(`search.webp`)을 쓴다.
   모바일에서 마지막 챕터와 다운로드 영역 사이 간격은 약 84px로 좁혔다(이전 296px).
4. 스크롤 등장 연출: 제목은 줄 단위 마스크 상승, 나머지는 순차 페이드업, 구분선은 좌→우.
   각 영역 최초 진입 시 한 번만 재생. `html.js`일 때만 숨겨 JS 없이도 내용이 보이고,
   `prefers-reduced-motion`이면 연출 없이 바로 표시한다. `html.js`는 head의 블로킹 `/js-flag.js`가
   첫 페인트 전에 붙인다(모듈 스크립트에서 붙이면 콘텐츠가 보였다 사라지는 깜빡임). 첫 화면은
   IntersectionObserver 하단 여백 때문에 큰 뷰포트에서 하단 메타 줄이 안 나타났으므로 로드 직후 바로 재생한다.
5. 자연 스크롤로 되돌린다. 이전 홈의 단계 잠금(wheel/touch/key 가로채기)은 운영자가 새 시안을
   승인하면서 함께 폐기했다.
6. App Store 링크는 Apple 마케팅 가이드라인에 따라 직접 만든 버튼이 아닌 공식 배지
   (`app-store-badge-ko.svg`)를 비율 그대로 쓴다. 헤더의 텍스트 "앱 받기"에는 Apple 로고를 넣지 않는다.
   푸터의 Apple 상표 고지를 유지하고, 마케팅 문구에서는 `iOS` 대신 제품명 `iPhone`을 쓴다.
7. CSP(`default-src 'self'; style-src 'self'`) 때문에 인라인 script/style 속성과 외부 웹폰트를 쓰지 않는다.
   폰트는 기존 시스템 스택을 유지한다(Pretendard 미설치 환경은 Apple SD Gothic Neo/Noto Sans KR).
8. 홈 전용 스타일은 `home.css`로 분리하고, `styles.css`는 법률·공유·운영 중단 페이지 전용으로 남긴다
   (이전 홈 전용 규칙은 제거).

### 레이아웃 기준

- 첫 화면은 `100svh` 채움+하단 정렬을 쓰지 않는다. 큰 모니터에서 GNB 아래가 300~700px 비어 보였다(1920·2560 실측).
  헤더 바로 아래에서 시작해 GNB~첫 콘텐츠 간격은 데스크톱 50~115px이고, 폰 캡처는 화면 높이에 맞춰 줄여
  1280×720에서도 첫 화면 안에 다 들어오게 한다.
- 헤더 로고·버튼, 첫 화면, 챕터, 다운로드, 푸터의 좌우 끝선을 같은 콘텐츠 폭(1240px−여백)에 맞춘다.
- 디자인 변경 후에는 360·390·820·1280×720·1440×900·1920×1080·2560×1440 첫 화면을 캡처해 눈으로 확인하고,
  가로 넘침·요소 겹침·깨진 이미지·첫 화면 CTA 노출을 수치로 점검한다.

### 웹 접근성

운영자 지시로 WCAG 2.2 AA를 지킨다. 본문 바로가기 링크, 랜드마크·섹션 제목 연결, 장식 기호 `aria-hidden`,
모든 링크 44px 터치 영역과 포커스 표시, 대비 4.5:1(큰 제목 3:1) 이상, 모션 감소 설정 대응.
변경 시 axe-core(wcag2a·2aa·21aa·22aa·best-practice)로 데스크톱·모바일 위반 0건을 확인한다.

### 재검토 조건

Pretendard 자가 호스팅(용량 대비 효과), 길안내 실사용 영상 확보 시 챕터 3 교체,
Android 출시 시 배지 추가.
