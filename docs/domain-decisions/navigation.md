# 앱 내 길안내

경로 미리보기에서 출발한 뒤 카카오내비 KNSDK가 제공하는 iOS 네이티브 실주행 화면과
그 화면 위 모토맵 커스터마이즈에 관한 결정 기록이다.

관련 구현:

- `app/navi.tsx`
- `lib/navigation.ts`
- `modules/kakao-navi/ios/KNNaviPresenter.m`
- `modules/kakao-navi/ios/KNNaviTheme.m`

## 먼저 확인할 활성 원칙

1. 실주행 화면은 React Native·네이버 지도가 아니라 별도 `UIViewController`로 표시하는
   KNSDK `KNNaviView`다. 안내가 끝나도 라이더가 직접 종료할 때까지 안전운행 화면을 유지한다.
   종료·위험 제보 버튼은 일반 안내·안전운행에서 표시하고 지도 이동 등 다른 화면에서는 숨긴다(NAV-010).
2. 경로 계산 차종은 항상 이륜차로 유지한다. 커스텀 자차 이미지를 위해 자동차 경로로
   바꾸거나 `KNNaviView`의 공개 차종 API를 호출하지 않는다.
3. GPS 수신 여부, 안내·안전운행·지도 이동, 이탈·재탐색 등 어떤 상태에서도 KNSDK의
   `bike_on/off` 기본 캐릭터를 노출하지 않고 모토맵의 수신/미수신 커스텀 마커만 사용한다.
4. `정체·원활·없음` 범례와 교통 버튼은 혼잡도 경로선을 위한 의도된 교통정보 모드다.
5. 주행 중 하단 안내 문구는 유지하되 KNSDK가 장식으로 붙이는 카카오프렌즈 이미지는
   노출하지 않는다. 도착 결과 팝업도 계속 표시하지 않는다.
6. KNSDK 비공개 동작에 기대는 우회는 SDK 버전을 올릴 때 바이너리 동작과 실기기를 다시
   확인한다. 이 네이티브 화면의 변경은 OTA로 반영되지 않으며 새 앱 빌드가 필요하다.
7. 경로 미리보기 지도는 경로 주변 장소를 클러스터로 합치지 않는다. 미선택 장소는 원형,
   목적지는 핀으로 표시하고 현재 화면 영역의 개별 마커만 유지한다.
8. 경로 미리보기의 등록 장소는 전체 목록을 먼저 받지 않는다. 카메라가 멈춘 실제 화면보다
   50% 넓은 창을 기준으로 조회·렌더하며 전국 단위 범위에서만 전체 조회로 폴백한다.

## NAV-001 — 도착 후 안전운행 화면 유지

- 날짜: 2026-08-21
- 상태: 활성
- 관련 구현: `KNNaviPresenter.m`
- 관련 커밋: `d71e705`, `1bb30f2`, `fa7c64c`

### 배경

목적지에 닿는 순간 앱이 안내 화면을 자동으로 닫으면 입구나 주차 위치를 확인하는 중에
지도가 사라져 위험했다. 반대로 KNSDK 화면을 유지하면 경로 안내 요소는 사라지고 현재 위치,
속도, 주소, 교통정보만 남는 안전운행 상태로 전환된다. 이때 보이는 `정체·원활·없음` 범례는
별도 화면의 흔적이 아니라 앱이 켜 둔 `trafficMode:YES`의 KNSDK UI다.

### 결정

`guidanceGuideEnded`에서는 화면을 닫지 않고 주행 결과 팝업 없이 KNSDK 안전운행 상태로
넘긴다. 실제 종료는 우상단 `종료` 버튼을 누른 라이더가 결정한다. 안내 중과 안전운행 상태
모두 교통정보 모드를 유지한다.

### 검토한 대안과 시행착오

도착과 함께 자동 종료하는 방식은 화면 정리는 단순하지만 실제 도착 동선에서 지도가 가장
필요한 순간을 앱이 결정해 버렸다. 안전운행 화면을 다른 Expo 라우트로 오인해 JS에서 고치려는
접근도 적용 대상이 다르다. 해당 UI와 상태 전환은 모두 KNSDK 네이티브 내부에 있다.

### 영향과 재검토 조건

KNSDK가 안전운행 상태를 제거하거나 공식적인 종료 후 화면 API를 제공하면 다시 검토한다.
안전운행 화면에서 불필요한 SDK 버튼을 조정할 때도 안내 중 화면과 함께 실기기 검증한다.

## NAV-002 — KNSDK 기본 바이크 캐릭터를 선택 단계에서 차단

- 날짜: 2026-08-21
- 상태: 활성
- 관련 구현: `KNNaviPresenter.m`, `KNNaviTheme.m`
- 관련 커밋: `53aa54f`, `11a62ff`, `87e7330`, `ee89ce6`

### 배경

KNSDK 1.12.14는 커스텀 자차 이미지 네 장을 저장한 뒤에도 이륜차 경로면 내부
`carImageType:`을 2로 바꿔 `bike_on.png` 또는 `bike_off.png`를 선택한다. 안내 시작과
이탈·재탐색 뒤에 다시 커스텀 타입을 씌웠지만, 목적지 도착 후 안전운행 전환에서 같은
초기화가 반복돼 GPS 수신 때는 컬러 캐릭터, 미수신 때는 회색 캐릭터가 다시 나타났다.

### 결정

모토맵이 생성한 `KNNaviMapView` 인스턴스에는 커스텀 자차 타입 잠금을 표시한다. KNSDK의
내부 `carImageType:` 구현은 그대로 호출하되, 잠긴 인스턴스에 들어오는 모든 타입을 커스텀
타입 0으로 바꾼다. 이에 따라 SDK의 `GpsValid:`가 on/off 이미지를 교체해도 항상 모토맵이
제공한 초록/회색 이미지 배열 안에서만 고른다. 잠그지 않은 KNSDK 지도에는 원래 동작을
그대로 전달한다.

안내 시작 전에 잠금을 설치해 첫 프레임도 보호하고, 알려진 안내·안전운행 상태 전환 뒤에는
테마 재적용을 폴백으로 유지한다. 커스텀 이미지 네 장은 한 번만 생성해 반복 상태 전환의
비트맵 생성 비용을 없앤다.

### 검토한 대안과 시행착오

상태 콜백이 발견될 때마다 `applyCarTheme`를 추가하는 방식은 안내 시작, 첫 GPS, 경로 이탈,
재탐색까지는 막았지만 새 내부 전환을 놓칠 때마다 회귀했다. 모든 위치 업데이트마다 테마를
다시 그리면 기본 이미지가 잠깐 보일 수 있고 불필요한 렌더링 비용과 깜빡임을 만든다.
경로 차종을 자동차로 바꾸면 아이콘 문제는 피할 수 있어도 자동차 전용도로를 포함할 수 있어
안전 요구를 훼손하므로 선택하지 않는다.

### 영향과 재검토 조건

`carImageType:`은 KNSDK의 공개 API가 아니므로 메서드가 사라지면 잠금 설치는 조용히 실패하고
알려진 전환점의 재적용만 남는다. KNSDK 업그레이드 때 `setCustomCarImages:anchor:`,
`carImageType:`, `GpsValid:`의 동작과 안내 시작·GPS 유실/복구·도착 후 안전운행·지도 이동·
이탈/재탐색·주야간을 실기기에서 확인한다. 공식 API가 이륜차 커스텀 자차를 완전히 지원하면
비공개 우회를 제거한다.

## NAV-003 — KNSDK 수명주기 전달과 접근성 배열 결함 방어

- 날짜: 2026-08-23
- 상태: 활성
- 관련 구현: `KNNaviAppDelegateSubscriber.swift`, `KNSDKBridge.m`, `KNNaviPresenter.m`

### 배경

KNSDK 1.12.14 안내 화면에서 `accessibilityWithType:view:`가 `nil` 뷰를 `NSArray`에 넣어
종료되는 충돌이 두 경로에서 반복됐다. 하나는 전체 경로 화면의 지도 이동 타이머였고 하나는
메뉴 자동 닫힘 타이머였다. 특히 전자는 앱이 백그라운드인 이벤트가 포함돼 있었다. 동시에
카카오모빌리티 공식 연동 문서가 요구하는 `handleWillResignActive` 등 앱 수명주기 이벤트가
Expo 앱에서 KNSDK로 전달되지 않고 있었다. CocoaPods에 공개된 최신 버전도 1.12.14라 SDK
업데이트로 해결할 수 없는 상태였다.

### 결정

Expo AppDelegate subscriber로 비활성·백그라운드·포그라운드·활성·종료 이벤트를 KNSDK에
전달한다. 내비를 쓰지 않은 세션에서 SDK가 초기화되지 않도록 초기화 성공 뒤에만 전달한다.

SDK의 비공개 `accessibilityWithType:view:`는 ABI를 확인한 뒤 경계에서 호출한다. 그 메서드가
`nil` 배열 원소로 발생시킨 `NSInvalidArgumentException`만 잡아 `accessibilityElements`를
`nil`로 되돌리고 UIKit의 기본 탐색에 맡긴다. 다른 예외는 숨기지 않고 다시 던진다.

### 검토한 대안과 시행착오

안내 화면 전체의 접근성을 끄면 충돌 가능성은 줄어도 보조 기능을 훼손한다. 모든 Objective-C
예외를 삼키면 별개의 SDK 결함을 감춘다. SDK 내부 타이머나 화면 전환을 비공개 API로 막으면
메뉴·전체 경로 기능이 달라질 수 있어 채택하지 않았다. 메인 스레드 HTTP 동기 대기로 잡힌
2초 앱 멈춤은 같은 SDK 내부 구현이지만 앱 경계에서 비동기로 바꿀 수 없어 별도 추적한다.

### 영향과 재검토 조건

이 변경은 네이티브 빌드가 필요하다. KNSDK가 1.12.14보다 새 버전을 공개하면 우선 업그레이드해
충돌 재현과 `accessibilityWithType:view:` ABI를 확인하고, 공급사에서 nil 방어를 추가했다면
앱의 예외 경계를 제거한다. 앱 멈춤이 빈번해지거나 3초 이상으로 늘면 KNSDK 공급사 문의와
대체 화면을 검토한다.

### 2026-10-10 scene 설정 전환의 준비 확인

Expo 57.0.27의 scene delegate는 앱의 AppDelegate로 활성·비활성·foreground·background
이벤트를 전달한다. 기존 KNSDK subscriber와 초기화 후 전달 guard를 유지하고 scene에 별도
중복 observer를 추가하지 않는다. 이 경로는 설치된 소스에서 확인했으며 실제 길안내 수명주기
검증은 남아 있다. 상세 경계는 REL-007과 패키지 업그레이드 계획을 따른다.

## NAV-004 — 하단 안내의 카카오프렌즈 장식 제거

- 날짜: 2026-08-24
- 상태: 활성
- 관련 구현: `KNNaviPresenter.m`

### 배경

KNSDK 1.12.14는 주행 중 GPS·경로 상태 등을 알리는 하단 `KNInfoView` 안의
`InfoTitleLabel`에 `chr_*.png` 카카오프렌즈 이미지를 표시한다. 도착 결과 팝업은 이미
`isShowDriveResultDialog:NO`로 끄고 기본 이륜차 자차 캐릭터도 커스텀 이미지로 차단했지만,
이 안내 장식은 서로 다른 내부 경로라 계속 노출됐다. 공개 `KNNaviView` API에는 이 이미지만
끄거나 교체하는 설정이 없다.

### 결정

`InfoTitleLabel`의 원래 `layoutSubviews`가 끝난 뒤 `titleImgView`만 숨긴다. 안내 문구와 닫기
동작은 그대로 두고, 캐릭터가 왼쪽에 가로로 배치된 경우에만 비워진 공간을 문구 너비로
돌린다. 메서드 시그니처와 두 객체 ivar의 타입을 먼저 확인하고, 구조가 다르면 아무 변경도
하지 않는다.

도착 결과 팝업을 계속 숨기고 커스텀 자차 이미지 잠금도 유지한다. 즉 캐릭터 제거를 위해
안내 상태 자체나 안전 관련 문구를 누락시키지 않는다.

### 검토한 대안과 시행착오

`KNInfoView` 전체를 숨기면 캐릭터와 함께 GPS 오류·경로 상태 같은 중요한 문구도 사라져
선택하지 않았다. SDK의 `chr_*.png` 파일을 빌드 산출물에서 교체하면 리소스 무결성과 SDK
업데이트에 더 취약하고, 여러 화면에 의도하지 않은 영향을 줄 수 있다. 캐릭터 영역만 숨긴 뒤
공간을 그대로 남기는 방식도 레이아웃이 어색해 문구가 안전하게 확장되는 경우에만 회수한다.

### 영향과 재검토 조건

네이티브 빌드가 필요하다. KNSDK 업그레이드 때 `InfoTitleLabel`, `titleImgView`, `titleLabel`,
`layoutSubviews` 구조와 주행 중 하단 안내, GPS 유실/복구, 경로 이탈·재탐색, 주야간 전환을
실기기에서 다시 검증한다. 공식적인 장식 이미지 표시 설정이 추가되면 비공개 우회를 제거한다.

## NAV-005 — 경로 미리보기에서도 장소를 개별 마커로 보여준다

- 날짜: 2026-08-25
- 상태: 활성
- 관련 구현: `components/navi/PreviewMap.tsx`

### 배경

메인 지도는 등록 장소를 클러스터로 합치지 않도록 바뀌었지만 경로 미리보기는 과거의
`clusters`와 클러스터 리프 탭 우회를 계속 사용했다. 같은 장소가 메인 지도에서는 바로
보이고 미리보기에서는 숫자 집계로 묶여 화면에 따라 발견 방식과 마커 의미가 달라졌다.

### 결정

경로 미리보기에서도 현재 화면 영역으로 거른 등록 장소와 일반 장소 즐겨찾기를 각각 네이티브
마커로 그린다. 경로 주변의 미선택 장소는 메인 지도와 같은 원형 마커로, 현재 목적지는 같은
장소의 핀 마커로 표시한다. 장소명은 줌 8부터 충돌하지 않는 범위에서 표시하고 마커 탭은 개별
오버레이의 직접 이벤트로 장소 미리보기를 연다. 출발점과 경유지는 장소보다 높은 우선순위를
유지한다.

### 검토한 대안과 시행착오

과거에는 이 화면에서 개별 마커 탭이 전달되지 않아 검증된 클러스터 리프 이벤트를 우회로
사용했다. 현재 메인 지도와 다른 지도 화면들이 같은 정적 이미지 개별 마커의 직접 탭을 사용하고
있으므로, 별도 집계 레이어와 캡션 전용 투명 마커를 유지할 이유가 없어졌다.

### 영향과 재검토 조건

경로가 전국 단위여도 카메라가 멈춘 현재 영역의 장소만 렌더하는 기존 뷰포트 필터는 유지한다.
실기기에서 미리보기의 장소 탭이 누락되거나 한 화면의 마커 수가 크게 늘어 입력 지연이 확인되면
클러스터를 되살리기보다 메인 지도와 같은 여유 창 기반 windowing을 먼저 적용한다.

## NAV-006 — 경로 미리보기 장소 조회도 실제 지도 창으로 제한한다

- 날짜: 2026-08-26
- 상태: 활성
- 관련 구현: `components/navi/PreviewMap.tsx`, `hooks/usePlaces.ts`

### 배경

NAV-005는 화면 안의 마커만 네이티브 지도에 올렸지만 데이터는 먼저 `all_places`로 전부 받은 뒤
클라이언트에서 걸렀다. 현재 장소 수에서는 동작해도 전국 데이터가 늘면 미리보기 한 번마다 필요
없는 행의 전송·변환·메모리가 함께 증가한다. 메인 지도에는 이미 실제 SDK region과 캐시 스냅을
사용하는 범위 조회·windowing이 검증돼 있었다.

### 결정

- 미리보기 첫 프레임은 목적지와 줌 12를 기준으로 제한된 주변 장소를 조회한다.
- 카메라가 멈추면 SDK의 중심·줌·region을 `usePlaces`에 전달한다. 서버 조회와 네이티브 마커
  렌더는 메인 지도와 같은 가로·세로 1.5배 여유 창을 사용한다.
- 카메라 이동 프레임마다 요청하지 않고 idle에서만 갱신한다. 캐시 좌표 스냅과 반경 여유,
  195km 이상에서 작은 등록 장소 테이블 전체로 폴백하는 규칙도 공통 훅을 그대로 사용한다.
- 일반 장소 즐겨찾기는 사용자별 전체 즐겨찾기 캐시를 재사용하되 같은 렌더 창으로 제한한다.

### 검토한 대안과 시행착오

경로선 주변 버퍼만 조회하면 실제 사용자가 지도를 옆으로 움직여 살펴보는 장소를 놓친다. 반대로
화면 영역을 서버에 사각형으로 넘기는 새 RPC는 더 정확하지만 기존 원형 범위 RPC와 캐시 규칙을
중복 구현해야 한다. 현재 규모에서는 검증된 `usePlaces` 범위 조회를 재사용하는 편이 단순하고
충분하다.

### 영향과 재검토 조건

경로가 전국 단위로 화면에 맞춰지면 전체 조회 폴백이 의도대로 동작한다. 일반적인 짧은 경로,
장거리 경로, 빠른 확대·축소·패닝 뒤 가장자리 마커와 목적지 핀을 확인한다. 등록 장소가 크게
늘어 전체 폴백도 무거워지면 bbox 전용 RPC나 경로 버퍼 조회를 추가한다.

## NAV-007 — 자동차전용도로 오진입 안전 안내

- 날짜: 2026-08-26
- 상태: 보류
- 예상 구현: `modules/kakao-navi/ios/KNNaviPresenter.m`, `modules/kakao-navi/ios/KakaoNaviModule.swift`, `lib/guideEvents.ts`
- 배포 조건: 새 네이티브 빌드 필요

### 배경

이륜차 경로는 자동차전용도로를 회피하지만, 라이더가 경로를 잘못 읽거나 GPS·도로 구조 때문에
실제로 자동차전용도로에 진입할 가능성까지 없앨 수는 없다. 이때 모토맵이 정확한 행동요령을
짧게 알려주면 안전에 도움이 된다. 다만 길안내 중 화면을 크게 가리거나 오탐 알림을 반복하면
그 자체가 주행을 방해할 수 있으므로 표시 가능성보다 감지 정확도와 방해 최소화가 더 중요하다.

현재 KNSDK 길안내 화면 위에는 네이티브 액션시트와 알림을 표시할 수 있어 커스텀 안전 UI도
구현 가능하다. 반면 공개 위치 정보의 `roadType`은 고속도로·일반도로 정도만 구분하고
자동차전용도로 여부를 직접 제공하지 않는다. `KNRouteAvoidOption_MotorWay`는 경로 탐색용 회피
옵션이므로 실제 진입 판정 신호로 그대로 사용할 수 없다.

### 구현 시 지킬 조건

- React Native 모달이 아니라 현재 KNSDK 길안내 `UIViewController` 위의 네이티브 오버레이로
  표시한다. 다음 회전, 차선과 현재 위치 등 핵심 안내 영역을 가리지 않는 작은 배너 또는 시트로
  시작하고 길안내와 음성 안내는 계속 동작시킨다.
- 단일 GPS 샘플이나 도로명만으로 경고하지 않는다. 도로 유형 변화, 연속 위치 판정, 경로 이탈·
  재탐색 상태와 진행 방향을 조합하고 동일 상황에서는 한 번만 알리는 히스테리시스와 쿨다운을
  둔다. 평행 일반도로·진입로·터널에서 오탐을 실기기로 검증한다.
- 자동 판정의 신뢰도가 충분하지 않으면 불확실한 자동 경고를 출시하지 않는다. 길안내 메뉴에서
  라이더가 직접 여는 `자동차전용도로 진입 도움`을 폴백으로 함께 검토한다.
- 알림은 짧은 제목, 핵심 행동요령, 큰 확인 동작만 제공하며 반복 애니메이션이나 긴 설명을
  사용하지 않는다. 필요하면 짧은 햅틱·음성을 한 번만 제공한다.
- 행동요령은 구현 시점에 경찰청·도로교통 관련 공식 지침을 다시 확인해 확정한다. 현재 후보인
  `가장 가까운 갓길 등 안전한 곳에 정차한 뒤 경찰에 도움을 요청`도 급정지·갓길 접근 위험과
  도로별 상황을 포함해 공식 근거를 확인하기 전에는 확정 문구로 사용하지 않는다.

### 영향과 재검토 조건

KNSDK가 현재 링크의 자동차전용도로 속성이나 공식 진입 이벤트를 제공하면 이를 최우선 신호로
사용한다. 공개 신호가 없으면 별도 도로 링크 데이터의 정확도·라이선스·오프라인 동작까지 검토한
뒤 구현 여부를 결정한다. 새 네이티브 빌드를 준비할 때 감지 프로토타입과 실기기 주행 테스트
계획을 함께 세우고, 공식 행동요령 검증이 끝난 뒤에만 사용자에게 노출한다.

## NAV-008 — 경로 미리보기의 현재 위치 구독은 화면이 소유한다

- 날짜: 2026-10-11
- 상태: 내부 기본 경로·안내 전환 사용자 확인 완료 / 반복 자원 효과 미확정
- 관련 기록: MAP-037, PERF-004

가려진 지도 홈의 센서를 중지하면 경로 미리보기의 현재 위치·실주행/시뮬레이션 판정도
과거 홈 위치에 의존해서는 안 된다. 미리보기는 자신의 화면이 포커스되고 앱이 active일 때
위치만 구독한다. 지도 홈과 같은 High/10m 조건과 MAP-036 cleanup을 재사용하고 방향 watch는
만들지 않는다. KNSDK 안내가 시작되거나 다른 장소 오버레이가 앞에 오면 이 구독도 중지한다.
카메라·경로 출발점 편집 규칙·이륜차 경로·SDK 안내 GPS와 백그라운드 처리는 변경하지 않는다.

후속 로컬 번들 검사에서 `@react-navigation/native` 직접 import는 Expo 57의 Router 호환성
검사에 거부됐다. 기존 지도와 같은 `expo-router/react-navigation`의 useIsFocused로 수정했다.
검사 비활성화 환경 변수나 별도 navigation 의존성 설치로 우회하지 않는다.

## NAV-009 — 경유지 폴백은 도로 단절만 해결하고 설정 실패는 반복 호출하지 않는다

- 날짜: 2026-10-11
- 상태: 소스·대역 테스트 검증 / 수정본 실기기 장애 주입 대기
- 관련 구현: `lib/kakaoNaviInit.ts`, `lib/kakaoRouteErrors.ts`, `hooks/useBikeRoutes.ts`, `app/navi.tsx`
- 관련 기록: PROVIDER-001, REL-007

기존 훅은 20413 외 모든 오류에서 경유지 축소 사다리를 계속 진행하고, 마지막 실패의 종류와
무관하게 코스 출발지로 다시 요청했다. 인증·서버·연결 실패도 여러 요청과 잘못된 코스 폴백으로
이어질 수 있었다. 초기화 Promise는 false 응답도 성공으로 캐시하고 실패 원문을 보존했다.

- 경유지 축소는 20412만 허용한다. 코스 출발지 폴백은 출발지/경유지 단절·이륜차 연결 없음
  (20410·20412·20413)만 허용하고 목적지 단절·서버/인증 실패는 오류 카드로 종료한다.
- C101(키 누락/미등록), G401(인증 실패)은 `kakao-navi` 기능을 프로세스 안에서 차단한다.
  다시 시도 버튼을 숨기고 옵션 변경·화면 재진입·안내 시작에도 초기화/요청을 반복하지 않는다.
- C103은 연결·인증 실패가 섞인 코드이므로 원문 문자열 추측으로 설정 실패로 확정하지 않는다.
  자동 사다리/코스 재요청은 하지 않되 사용자의 명시적 재시도는 허용한다. C020/G5xx와
  잘못된 응답도 같은 입력으로 경유지를 줄여 해결하려 하지 않는다.
- 동시 초기화와 성공 후 진입은 같은 Promise를 공유한다. false는 성공으로 캐시하지 않고,
  동기 예외와 reject는 원문 없는 ProviderError로 변환한다. 미지원 기기·키 누락은 호출하지 않는다.
- 기존 20초 UI 제한과 늦은 응답 무시는 유지한다. 네이티브 Promise를 취소할 수 있다고
  가정하지 않으며 아직 끝나지 않은 초기화에 중복 초기화를 겹쳐 시작하지 않는다.
- 원문·키·좌표를 오류 상태에 저장하지 않는다. SDK 브리지가 전달하는 허용 코드만 남기고
  초기화·경로·후처리 실패를 오류 카드/지도 복귀로 마무리한다. 이륜차 회피·경로선은 그대로다.

설치한 KNSDK 1.12.14의 `KNError.h`와 [공식 오류 안내](https://developers.kakaomobility.com/guide/ios/solution.html)를
대조했다. 문서와 SDK 코드가 완전히 같지는 않아 확인되지 않은 코드의 의미를 추측하지 않는다.
초기화·실제 훅 대역 테스트는 호출 수·취소·20초 뒤 응답·폴백 보존을 확인했다. 네이티브 코드는
바꾸지 않았고 수정본 실기기/공급자 장애 주입·TestFlight 검증은 별도로 남는다.

## NAV-010 — 지도 이동 화면에서는 커스텀 종료·위험 제보 버튼을 함께 숨긴다

- 날짜: 2026-10-16
- 상태: 1.2.9(39) 실기기 사용자 테스트에서 버튼 잔류 보고 / 미해결·원인 재조사
- 관련 구현: `modules/kakao-navi/ios/KNNaviPresenter.m`
- 관련 기록: NAV-001, REL-001, REL-003

### 배경

길안내 중 지도를 스와이프하면 SDK 화면이 지도 이동 모드로 전환되지만, 모토맵이 별도로
붙인 종료·위험 제보 버튼은 남아 있었다. 기존 제약은 상하단 SDK 뷰에 연결돼 있지만
화면 모드에 맞는 표시 처리는 없었다. SDK 내부 뷰의 숨김·프레임 변경을 계속 추적해
다른 위치를 추정하기보다 공개 화면 상태 콜백을 사용한다.

### 결정

- `naviViewScreenState:`의 `DriveNormal`·`SafetyNormal`에서만 실주행 커스텀 버튼을 표시한다.
  `DriveTouch`·`SafetyTouch`·전체 경로·구간 정보·기타 상태에서는 두 버튼을 함께 숨긴다.
- SDK가 일반 안내·안전운행으로 돌아오면 기존 위치와 종료/제보 동작을 복원한다.
  지도 이동 중 종료하려면 먼저 SDK의 안내 화면으로 복귀한다. 도착 시 자동 종료하지 않는다.
- 마지막 화면 상태를 저장해 `startWithTrip` 중 버튼 생성 전에 도착한 콜백도 반영한다.
  첫 상태 콜백을 받기 전에는 기존 버튼 표시를 유지해 SDK가 초기 콜백을 생략해도 종료
  수단이 사라지지 않게 한다. `hidden`으로 터치·접근성 탐색도 함께 차단한다.
- 시뮬레이션에는 커스텀 버튼을 만들지 않고 기존 SDK 종료 UI를 유지한다.
  SDK 자차 잠금·안전운행 테마 복구·지도 제스처·길안내 수명주기는 변경하지 않는다.
- 네이티브 UI 변경은 OTA로 적용할 수 없다. 다음 후보 1.2.9 / native 3 / API 1로 분리하고,
  새 빌드·설치·공개 배포는 별도 승인 후 진행한다.

### 검토한 대안과 재검토 조건

SDK 내부 배너의 프레임을 고빈도로 읽어 버튼을 재배치하는 방법은 화면별 겹침·애니메이션
타이밍에 의존하므로 채택하지 않았다. 공개 상태 콜백을 이용한 숨김/복원이 더 작은 변경이다.
상태 콜백으로 제어되는 UIButton 표시 검사는 실제 SDK 스와이프·복귀 동작 검증과 구분한다.
새 바이너리에서 지도 이동·전체 경로·구간 정보·도착 후 안전운행·시뮬레이션을 확인해야 한다.
SDK 상태 enum·콜백 순서가 바뀌면 초기 표시 폴백과 정상 화면 복원을 다시 검증한다.

### 로컬 검증 범위

설치된 KNSDK 1.12.14 공개 헤더로 수정 전후 presenter 전체의 iOS Simulator 대상
Objective-C 컴파일을 통과했다. UIKit에서 실제 presenter 콜백과 UIButton을 실행한

## NAV-011 — 안내 음성 동안만 다른 앱 오디오를 낮추고 종료 후 우선권을 돌려준다

- 날짜: 2026-10-17
- 상태: 로컬 구현·정책 검증 / 실제 동시 재생 검증 전
- 관련 구현: `KNNaviAudioFocus.h/.m`, `KNNaviPresenter.m`, `tests/ios/`,
  `scripts/test-ios-navigation-audio.sh`

### 배경과 원인 확인

사용자가 음악·영상 소리에 길안내 음성이 묻힌다고 보고했다. 기존 `KNSDKBridge`는
SDK 초기화 전에 Playback + MixWithOthers를 활성화하고, presenter의 음성 시작·종료
콜백은 비어 있었다. 실제 presenter 콜백을 호출한 simulator 정책 검사의 초기/안내 중/
종료 후 categoryOptions는 **1 → 1 → 1**로 안내 중 DuckOthers가 없었다. 이는 정책 결함의
재현이며 실제 두 앱 소리의 음향 크기를 측정한 검사는 아니다.

설치된 KNSDK 1.12.14 공개 `KNGuidance.h`는 음성 콜백을 메인 스레드에 전달한다.
실제 SDK 바이너리에서 `willPlayVoiceGuide`가 AVAudioPlayer.play 직전에 실행되고,
정상 종료 뒤에는 같은 KNGuide_Voice 객체로 didFinish가 전달되는 것을 확인했다.
stopAllSound는 취소한 현재·대기 음성에도 종료 콜백을 예약하므로, 시작하지 않은 음성의
종료와 지연 종료가 현재 음성의 우선권을 해제하지 않게 해야 한다.

### 결정

- SDK 초기화의 mix-only 설정은 유지한다. 화면이 열려 있는 동안 계속 감쇠하지 않는다.
  실제 음성 시작 직전에만 Playback/Default + MixWithOthers + DuckOthers +
  InterruptSpokenAudioAndMixWithOthers를 적용하고 활성화한다. 시작 시에는 먼저
  비활성화하지 않아 재생 중인 소리를 잘라낼 위험을 줄인다.
- 음악·영상은 iOS에 감쇠를 요청하고, spokenAudio로 분류된 다른 앱 음성 콘텐츠는
  일시 중단을 요청한다. 다른 앱의 분류·복원 동작은 해당 앱과 iOS 정책에 달려 있다.
  다른 앱을 직접 조작하거나 시스템 음량·스피커 출력·Bluetooth 경로를 강제로 바꾸지 않는다.
- 시작한 음성을 객체 동일성 집합으로 보관한다. 중복 시작/종료와 미재생 대기 음성의
  종료는 무시하고 마지막 활성 음성의 종료 때만 세션을 비활성화하며
  NotifyOthersOnDeactivation으로 다른 앱 재개를 알린다. 이전 category/mode/options를
  복원하고 다음 음성까지 비활성 상태를 유지한다. 세션 active 여부의 비공개 getter는 쓰지 않는다.
- 초기 설정/활성화 실패는 숫자 오류 코드만 기록하고 기존 음성 재생을 막지 않는다.
  복원이 실패하면 원래 snapshot을 버리지 않고 다음 안내/종료에서 먼저 재시도한다.
  감쇠 설정을 새 기준으로 저장하는 실패 회귀를 방지한다.
- 길안내 종료는 SDK 재생을 멈춘 뒤 강제 정리하고 늦은 시작을 거부한다. 전화 등 오디오
  중단 때도 활성 음성을 비우고 우선권을 돌려준다. 중단 종료 시 임의 재생/활성화를 하지 않고
  다음 안내를 기다린다. 앱 백그라운드 진입 자체로는 재생 중인 안내를 끊지 않는다.
- 도착 후 안전운행 화면은 유지하며 이후 안전 안내에도 같은 정책을 사용한다.
  기존 시작 안내 멘트 생략·음량·UI·GPS 정책은 바꾸지 않는다.

### 검증과 배포 경계

수정 후 실제 presenter 콜백과 simulator AVAudioSession에서 **1 → 19 → 1**로 안내 중
감쇠/음성 우선 옵션과 종료 후 복원을 확인했다. helper의 동일 객체·겹치는 시작·대기 음성
취소·중복/지연 종료·전화 중단·늦은 시작·설정/활성화/복원 실패는 별도 정책 fixture로 검사한다.
재현 가능한 `bash scripts/test-ios-navigation-audio.sh`는 격리한 임시 simulator를 생성해
helper 정책과 실제 시스템 옵션을 검사하고 생성한 simulator/app만 정리한다.
