# 서비스 운영 중단과 재개

## OPS-001 — 위치기반서비스 관련 절차 정비 전까지 전체 서비스 중단

- 날짜: 2026-08-28
- 상태: 활성
- 관련 구현: `app/_layout.tsx`, `components/ServiceSuspendedScreen.tsx`, `website/src/index.js`, `README.md`

### 배경

모토맵은 지도 주변 검색과 경로 요청 과정에서 이용자의 위치를 사업자 시스템 또는 외부 API에
전송하고, 1.2.0부터는 앱 내 길안내도 제공한다. 위치기반서비스사업 신고 대상 여부와 필요한
운영 요건을 공식 상담으로 확정하고 사업자 등록 등 선행 절차를 정비할 때까지 추가 제공을
계속하지 않기로 했다.

운영 중단은 적용 이후의 제공을 멈추는 조치다. 이미 제공한 기간을 소급해 없애거나 법률 판단을
대체하지 않는다.

### 결정

전체 서비스 중단은 다음 경계를 모두 충족해야 완료로 본다.

1. App Store에서 앱을 판매 중단해 신규 다운로드를 막는다. 앱 레코드는 삭제하지 않는다.
2. OTA를 받을 수 있는 모든 출시 런타임에는 초기화 전 운영 중단 화면을 배포한다. 중단 화면은
   지도, 위치 구독, 길안내 SDK, 인증, 푸시, 분석을 시작하지 않는다.
3. OTA를 지원하지 않거나 아직 OTA를 적용하지 않은 설치본을 위해 백엔드를 중단하고, 클라이언트에
   내장된 지도·검색·길안내 공급자 자격 증명도 비활성화한다.
4. `motomap.kr`의 소개·공유 화면은 503 운영 중단 안내로 대체한다. 이용약관, 개인정보 처리방침,
   위치기반 서비스 이용약관과 계정·데이터 요청 이메일은 계속 접근 가능해야 한다. 공개 저장소의
   `README.md`도 운영 중단과 재개 예정 시점을 알리고 App Store에서 바로 다운로드할 수 있는 것처럼
   안내하지 않는다.
5. 현재 제공 중인 기능의 이용자 데이터는 보존한다. 단, 1.1.0에서만 사용하고 현재 처리 목적이
   없는 전체 GPS 경로 `public.rides`는 RIDE-004에 따라 1.2.8 DB 정비 창에 파기한다. 운영 중단 중
   열람·삭제·처리정지 요청은 `starhn87@gmail.com`으로 접수해 처리한다.

운영 재개에는 최소한 다음 확인이 필요하다.

- 사업자 등록과 위치기반서비스사업 신고 완료. 주변 검색·날씨·유가·AI 추천·길안내 등 현재
  기능만으로 신고가 필요하며, 향후 라이딩 지도 구현 여부는 이 판단을 바꾸지 않는다.
- 위치정보 이용약관·개인정보 처리방침·보호조치와 App Store 고지의 일치
- 공식 상담 또는 전문 검토 결과 기록
- 중단한 백엔드와 외부 공급자 자격 증명의 복구, 앱 런타임별 재개 OTA 검증
- 재개 버전의 보안·릴리스 호환성 검사
- 백엔드·외부 공급자·재개 OTA와 알림 진입 화면의 정상 동작을 확인한 뒤, 보존된 푸시 토큰을
  대상으로 운영 재개 알림을 발송하고 앱 내 공지도 함께 노출

구체적인 재개 순서와 사용자 전환 방식은 OPS-002를 따른다. 활성 서비스 OTA나 운영 재개 푸시를
먼저 발행해 사용자가 복구 절차의 중간 상태에 진입하게 해서는 안 된다.

운영 재개 푸시는 실제 서비스 복구와 재개 OTA 적용을 검증하기 전에는 발송하지 않는다. 알림을
탭했을 때 중단 화면이나 오류 화면이 나타나지 않는지 실기기에서 먼저 확인하고, 발송 결과와 실패
건수를 재개 배포 기록에 남긴다.

운영 중단 중 사용 요청과 재개 일정 문의에는 `docs/customer-support-templates.md`를 우선
참조한다. 운영 재개는 2026년 9월 중으로 안내하되 정확한 일자가 확정되기 전에는 추측하지 않는다.
문의 언어로 불편을 먼저 인정한 뒤, 서비스가 실제 재개될 때 앱 푸시를 발송하고 `motomap.kr`에도
안내한다는 점을 알린다.

앱과 `motomap.kr`의 운영 중단 화면에는 `2026년 9월 중 운영 재개 예정`을 표시한다. 정확한 날짜가
확정되기 전에는 일 단위 약속이나 카운트다운을 노출하지 않고, 일정이 바뀌면 앱·웹·고객지원
템플릿과 이 기록을 같은 작업에서 동기화한다.

사업자 등록만 완료한 상태는 자동 재개 조건이 아니다.

모토맵은 위치정보를 다른 위치기반서비스사업자에게 공급하는 사업이 아니라 이용자의 위치를
자체 서비스에 사용하는 구조이므로, 현재 확인한 범위에서는 개인위치정보사업 등록이 아니라
위치기반서비스사업 신고를 운영 기준으로 삼는다. 외부 전문 검토에서 분류가 달라지면 근거를
기록한 후 이 결정을 대체한다.

구버전 중단 OTA를 발행할 때만 `MOTOMAP_EMERGENCY_RUNTIME_VERSION`을 대상 앱 버전으로 설정한다.
이 변수는 앱 버전과 `runtimeVersion: { policy: 'appVersion' }`을 함께 맞추는 비상 수단이며, 일반
빌드·OTA에서는 절대 설정하지 않는다. 대상 런타임과 발행 결과를 확인한 뒤 셸에서 해제한다.

운영 중단 자체처럼 안전 경계를 만드는 OTA는 계속 모든 도달 가능한 런타임에 발행한다. 중단
화면의 일정 문구처럼 안전과 무관한 변경은 REL-005에 따라 관측된 활성 런타임만 동기화할 수 있다.

### 검토한 대안과 시행착오

- App Store 판매 중단만으로는 기존 설치자와 구입 목록을 통한 재다운로드를 막지 못한다.
- 현재 런타임 하나에만 OTA를 발행하면 구버전 설치본이 계속 동작할 수 있다.
- Supabase만 중단하면 클라이언트 키로 직접 호출하는 지도·카카오 로컬·경로·길안내가 남는다.
- 원격 버전 정책은 해당 기능이 포함된 앱에서만 읽으므로 모든 출시본에 대한 중단 수단이 아니다.

따라서 스토어, 런타임별 앱, 백엔드, 외부 지도·길안내 공급자를 함께 중단한다.

### 영향과 재검토 조건

서비스 중단 또는 재개를 변경할 때는 이 문서를 가장 먼저 검토한다. 재개 시 이 항목을 삭제하지
않고 `대체됨`으로 표시한 뒤, 재개 조건과 실제 신고·검토 결과를 새 결정으로 연결한다.

운영 중단이 실제로 적용된 시각, 각 런타임 OTA 그룹, 백엔드·공급자·스토어 상태는 배포 기록에
남긴다. 비밀키나 계정 식별 정보는 문서에 기록하지 않는다.

## OPS-002 — 1.2.8 스토어 배포를 주 경로로 단계적으로 운영을 재개한다

- 날짜: 2026-08-29
- 상태: 활성(운영 재개 시 적용 대기)
- 관련 구현: 구현 전 — `components/ServiceSuspendedScreen.tsx`, `expo-updates`,
  `website/src/index.js`, `lib/push.ts`, `public.broadcast_notice`

### 배경

기본 EAS Update 동작은 앱을 처음 실행할 때 새 OTA를 내려받고 다음 실행에서 적용한다. 현재 운영
중단 번들은 실행 중 업데이트 확인·다운로드·재시작 기능을 포함하지 않으므로, 재개 당일 활성 OTA와
푸시만 발행하면 일부 사용자는 앱을 두 번 직접 종료·실행해야 한다. 운영 중단 중 앱을 한 번도 열지
않아 재개 연결 OTA를 받지 못한 설치본까지 푸시 탭 한 번으로 전환하는 것은 보장할 수 없다.

기존 `push_tokens`와 `public.broadcast_notice`로 운영 재개 알림을 보낼 수 있지만 알림 권한 해제,
앱 삭제, 토큰 만료 때문에 전원 도달을 보장할 수 없다. 현재 전체 공지 함수도 Expo Push ticket과
receipt를 회수해 무효 토큰을 정리하지 않으므로 재개 방송 전에 보완이 필요하다.

### 결정

운영 재개는 1.2.8 App Store 업데이트를 주 경로로 삼고, 구버전 OTA는 사용자를 최신 스토어
버전으로 연결하는 보조 수단으로만 사용한다. 사용자에게 `앱을 두 번 껐다 켜라`고 요구하지 않고,
재개 연결 화면의 버튼 한 번이 설치 상태에 따라 다음 동작을 선택하게 한다.

- 1.2.8 미만: App Store의 모토맵 업데이트 화면을 연다.
- 1.2.8이고 호환되는 OTA가 있음: `checkForUpdateAsync` → `fetchUpdateAsync` → `reloadAsync`로
  내려받은 뒤 앱을 즉시 다시 시작한다.
- 이미 최신 상태: 서비스를 바로 시작한다.
- 확인·다운로드 실패: 중단 화면을 유지하고 재시도와 App Store 폴백을 제공한다.

재개 연결 화면은 지도, 위치 구독, 인증, 길안내 SDK, 푸시 등록과 분석을 초기화하지 않는다.
`motomap.kr`의 최소 공개 상태 엔드포인트에서 `suspended`, `preparing`, `active`, 최소 앱 버전,
스토어 URL과 사용자 문구만 읽는다. 응답 실패, 스키마 오류 또는 알 수 없는 상태는 모두
`suspended`로 닫고, 상태 응답에는 비밀키나 사용자별 정보를 넣지 않는다.

다음 순서를 바꾸지 않는다.

1. 사업자 등록, 위치기반서비스사업 신고, 약관·개인정보 처리방침·보호조치 정비와 공식 상담
   기록을 완료한다.
2. 서비스가 계속 중단된 상태에서 재개 연결 화면과 상태 엔드포인트를 구현한다. 지원 중인 구버전
   런타임에는 서비스 모듈을 열지 않는 연결 OTA를 먼저 배포하고 실기기에서 실패 폐쇄를 검증한다.
3. 1.2.8은 별도 내부 테스트 채널과 격리된 테스트 환경에서 검증한다. 프로덕션 OTA와 App Store
   공개 상태는 이 단계에서 바꾸지 않는다.
4. 1.2.8 App Store 빌드는 원격 상태가 `suspended` 또는 `preparing`이면 중단 화면만 보이도록
   제출한다. 승인·스토어 가용성과 구버전의 스토어 이동을 확인한다.
5. 공개 진입은 계속 막은 채 production Supabase와 네이버·카카오 지도·길안내 설정을 복구한다.
   허용된 테스트 계정으로 인증, 위치 권한, 지도, 검색, 장소 상세, 길안내, 푸시와 계정 삭제를
   검증한다.
6. 1.2.8에 필요한 최종 OTA가 있으면 내부 채널에서 확인한 동일 산출물을 production 1.2.8
   런타임에 승격하고, 재개 버튼의 다운로드·재시작과 오류 폴백을 실기기에서 검증한다.
7. 백엔드·공급자·스토어·앱 진입 검증이 모두 끝난 뒤에만 공개 상태를 `active`로 전환한다.
   상태 전환 뒤 새 설치와 구버전 업데이트를 다시 확인한다.
8. 마지막에 `service_resumed` 운영 공지를 앱 내 알림과 푸시로 한 번 발송한다. 알림은 광고 문구를
   섞지 않고 `모토맵 운영을 다시 시작했어요`와 같이 운영 사실 및 앱 실행 방법만 안내한다.
9. Expo Push ticket·receipt, 무효 토큰, 앱 시작·업데이트 적용 실패, Sentry 오류를 확인한다.
   일시 실패만 제한적으로 재시도하고 `DeviceNotRegistered` 토큰은 제거한다. 발송 수·성공·실패와
   상태 전환 시각을 재개 배포 기록에 남긴다.

재개 방송은 캠페인 식별자로 멱등성을 보장해 중복 발송을 막는다. 푸시가 도달하지 않아도 App Store
자동 업데이트, 앱 직접 실행의 재개 연결 화면과 앱 내 공지가 같은 최종 상태로 수렴해야 한다.
향후 `push_tokens`에는 앱 버전·runtime·빌드 번호를 함께 갱신해 버전별 안내와 도달률 검증을
가능하게 한다.

### 검토한 대안과 시행착오

- 활성 OTA를 먼저 발행하고 `완전히 종료한 뒤 두 번 실행`하도록 안내하는 방식은 사용자가 적용
  여부를 알기 어렵고 중간 이탈이 커서 채택하지 않는다.
- 푸시만으로 백그라운드에서 OTA를 미리 적용하는 방식은 iOS 전달과 실행 시점이 보장되지 않고,
  현재 중단 번들에 백그라운드 적용 코드도 없어 재개 조건으로 삼지 않는다.
- 구버전 전체를 기능 OTA로 다시 여는 방식은 네이티브 계약이 다른 런타임을 장기 지원해야 하고
  재개 검증 범위를 넓힌다. 구버전은 연결 화면과 App Store 이동까지만 책임진다.
- 1.2.8 승인과 동시에 공개 상태를 여는 방식은 스토어 전파, 백엔드 및 공급자 복구의 순서가
  어긋났을 때 사용자가 부분 복구 상태를 보게 되므로 채택하지 않는다.

### 영향과 재검토 조건

현재 중단 번들을 적용한 적 없는 오래된 설치본이나 재개 연결 OTA를 받기 전에 장기간 앱을 열지
않은 설치본은 첫 실행 한 번만으로 전환되지 않을 수 있다. 이 한계는 숨기지 않고 1.2.8 스토어
업데이트를 공식 복구 경로로 제공한다. 재개 전에 App Store 자동 업데이트 보급률과 EAS Update
적용률을 확인하되, 보급률을 이유로 신고·보호조치 완료 전 서비스를 먼저 열지 않는다.

기존 바이너리의 업데이트 시작 동작을 네이티브 설정으로 바꾸는 것은 OTA로 소급 적용할 수 없다.
향후 새 중단 기능을 설계할 때에는 활성화와 복구를 한 쌍으로 구현하고, 중단 번들 자체에 안전한
상태 확인과 실행 중 업데이트 적용 수단을 포함한다.
