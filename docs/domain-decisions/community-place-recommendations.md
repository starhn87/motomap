# 일반 장소 추천

바이크 특화 장소로 검증되지 않은 일반 맛집·카페·명소도 라이더가 서로 소개할 수 있게 하면서,
모토맵 등록 장소의 보수적인 선별 신뢰도를 지키기 위한 결정 기록이다.

관련 구현:

- `public.general_places`, `public.general_place_shares`
- `components/map/TempPlaceSheet.tsx`, `components/map/MapHome.tsx`
- `components/place/RiderPlaceFacts.tsx`, `app/search.tsx`

## 먼저 확인할 활성 원칙

1. 일반 장소 상세의 행동은 `장소 추천하기`로 부르고, 설명에서 바이크 특화 장소가 아님을
   명시한다. 데이터 계약은 별도 `general_place_shares`를 유지한다.
2. 일반 장소 추천은 등록 승인이나 바이크 특화 검증을 뜻하지 않으며 자동 승격 근거로 쓰지 않는다.
3. 일반 추천 장소 마커는 등록 장소와 구분하고, 사용자가 `추천 장소` 필터를 켰을 때만 보인다.
4. 등록 장소에는 별도 좋아요·추천 리액션과 인기 순위를 표시하지 않는다. 즐겨찾기와 라이더 제공
   정보는 목적이 다른 신호이므로 데이터가 충분해지기 전까지 인기 점수로 합산하지 않는다.
5. 주유소 일반 장소에는 `장소 추천하기`를 표시하지 않는다. 주유소는 유가·길안내를 위한 별도
   실용 레이어로 다루며 일반 맛집·카페·명소 추천 신호와 섞지 않는다.

## COMMUNITY-001 — 일반 장소 추천과 바이크 특화 등록을 분리한다

- 날짜: 2026-08-24
- 상태: 대체됨(COMMUNITY-003, COMMUNITY-004)
- 관련 구현: `public.general_places`, `docs/submission-approval-policy.md`

### 배경

라이더는 바이크 전문점이 아니어도 라이딩 중 들른 맛집·카페·명소를 다른 라이더와 공유하고 싶을
수 있다. 이를 기존 장소 제보로 승인하면 한 사람의 취향이 바이크 특화 검증처럼 보이고, 반대로
현재의 보수적인 `PLACE-RIDER-VALUE` 기준으로 반려하면 일반 목적지를 나누는 참여 자체가 막힌다.

### 결정

- 일반 장소 상세에서 로그인한 사용자가 추천 이유를 하나 이상 선택해 추천하거나 취소할 수 있다.
- 이유는 `음식`, `커피`, `경치`, `라이딩 중 들르기`, `여럿이 방문`, `바이크 주차`의 고정 집합으로
  시작한다. 자유 문구와 사진은 추천에 중복 저장하지 않고 리뷰에 남긴다.
- 추천은 운영자 승인 없이 즉시 반영한다. 계정당 장소별 하나만 허용하고, 사용자는 자기 추천만
  읽고 쓰며 공개 화면에는 사용자 식별자 대신 집계만 보인다.
- 추천이 한 건이면 상세와 별도 추천 필터에서 노출할 수 있다. 초기 사용자 수가 적으므로 두 건
  이상의 임계값을 두지 않는다.
- 등록 장소에는 이 설명과 추천 UI를 표시하지 않는다. 일반 장소가 등록 승격되면 추천 행은 향후
  등록 해제 가능성에 대비해 보존하되 공식 장소 경험에는 사용하지 않는다.

### 검토한 대안과 시행착오

- 추천마다 Discord 승인을 받으면 일반 목적지 공유의 즉시성이 사라지고 기존 장소 제보와 다시
  같아지므로 채택하지 않는다.
- 추천을 즐겨찾기나 별점으로 추정하면 개인 저장·장소 평가와 다른 사람에게 소개하려는 의도를
  구분할 수 없어 별도 명시적 신호를 사용한다.
- 추천 수가 쌓이면 자동으로 등록 장소로 승격하는 방식은 바이크 접근성·안전·반복 이용 근거를
  확인하지 못하므로 금지한다.

### 영향과 재검토 조건

한 추천은 공식 제보 심사의 독립적인 바이크 관련성 근거가 아니다. 여러 계정의 추천·리뷰·실제
라이딩 기록이 쌓이면 운영자가 조사할 후보 신호로만 사용하고, 승격은 기존 승인 기준과 사람의
최종 판단을 그대로 거친다. 스팸 추천이나 한 화면의 추천 마커가 크게 늘면 추천 최소 계정 신뢰도,
지역별 노출 상한과 신고 흐름을 재검토한다.

## COMMUNITY-002 — 추천 장소는 별도 지도 레이어로만 발견시킨다

- 날짜: 2026-08-24
- 상태: 대체됨(COMMUNITY-004)
- 관련 구현: `components/map/CategoryFilter.tsx`, `components/map/MapHome.tsx`, MAP-020

### 배경

추천 일반 장소를 등록 장소와 함께 기본 노출하면 중립 마커를 쓰더라도 사용자는 둘 다 모토맵이
검증한 장소로 받아들일 수 있다. 일반 장소 수가 늘면 지도 밀도와 네이티브 오버레이 수도 함께
증가한다.

### 결정

- 지도 카테고리 행에 별도 `라이더 추천` 필터를 두고, 사용자가 켰을 때만 추천 일반 장소를
  조회·표시한다.
- 추천 마커는 카테고리 색을 쓰지 않는 중립 원형 이미지로 표시한다. 선택되었을 때만 기존 일반
  장소와 같은 핀으로 바뀐다.
- 서버 조회와 마커 마운트는 MAP-020의 실제 지도 영역·50% 여유 windowing을 따른다.
- 추천 목적지 화면에는 등록 장소와 분리된 `라이더가 추천하는 곳` 섹션으로 제공한다.

### 영향과 재검토 조건

추천 필터를 끄면 현재 등록 장소 지도는 완전히 동일하게 유지된다. 추천 레이어 활성 화면에서
마커가 250개를 넘거나 입력 지연이 확인되면 클러스터보다 거리·추천 수·최근성 기반 상한을 먼저
도입한다. 필터 발견성이 낮으면 기본 노출로 바꾸기보다 추천 목적지 섹션의 진입률을 먼저 개선한다.

## COMMUNITY-003 — 등록 장소의 명시적 추천으로 TOP 5를 정한다

- 날짜: 2026-08-24
- 상태: 대체됨(COMMUNITY-006)
- 관련 구현: `public.place_recommendations`, `components/place/RiderPlaceFacts.tsx`, `app/search.tsx`

### 배경

라이더 제공 정보와 주행 기록만으로 순위를 만들면 장소의 객관적인 편의나 방문 횟수를 다른
라이더에게 권한다는 의사로 오해하게 된다. 반대로 추천만 보여주면 정보가 적은 초기에는 동률이
많아 순위가 불안정하다.

### 결정

- 등록 장소 상세의 `라이더 제공 정보` 제목 오른쪽에 유니코드 이모지가 아닌 벡터 원형 체크
  아이콘과 `추천하기`
  버튼을 둔다. 추천 후에는 채워진 체크와 `추천함 · N`으로 표시한다.
- 즐겨찾기는 개인 저장이고 추천은 공개 집계에 반영되는 의사다. 계정당 장소별 하나만 허용하며
  탭 즉시 낙관적으로 반영하고 실패하면 원복한다. 선택 상태와 집계 변화가 성공 피드백이므로
  별도 성공 토스트는 띄우지 않고, 로그인 필요와 실패만 알린다.
- 검색 첫 화면의 `라이더 추천 TOP 5` 후보는 명시적 추천이 한 건 이상인 활성 등록 장소뿐이다.
  후보가 5개보다 적으면 라이더 제공 정보만으로 자리를 채우지 않는다.
- 순위는 고유 추천자 수를 가장 먼저 비교하고, 동률이면 고유 방문 라이더 수, 리뷰의 평점·개수,
  라이더 제공 정보 확인 수, 최근 추천 시각 순으로 정한다. 원시 사용자 식별자는 공개하지 않는다.
- 장소가 일반 장소로 전환되어도 추천 행은 보존하지만 일반 장소 공유로 자동 변환하지 않는다.
  `검증된 장소를 추천`한 의사와 `일반 장소를 공유`한 의사는 같지 않기 때문이다.

### 검토한 대안과 시행착오

- 라이더 제공 정보 확인 수를 추천으로 간주하면 `바이크 주차 가능` 같은 사실 확인이 추천으로
  과장되므로 채택하지 않는다.
- 출발·도착·공유 기본 행동 행에 추천을 넣으면 지도 행동과 평가 행동이 섞이고 버튼 너비가
  줄어들어, 관련 정보 섹션의 제목 행에 배치한다.
- 이모지는 기기별 형태와 기준선이 달라지므로 사용하지 않고 앱의 SVG 아이콘으로 통일한다.

### 영향과 재검토 조건

추천 취소는 즉시 집계에서 빠진다. 추천 수가 늘어 특정 지역이나 인기 장소에만 순위가 고착되면
기간별 추천이나 지역별 TOP을 검토하되, 객관 정보만으로 추천 후보를 만드는 경계는 유지한다.

## COMMUNITY-004 — 일반 장소는 추천이 아니라 라이더 공유로 발견시킨다

- 날짜: 2026-08-24
- 상태: 대체됨(COMMUNITY-005)
- 관련 구현: `public.general_place_shares`, `components/map/TempPlaceSheet.tsx`, `components/map/MapHome.tsx`

### 배경

일반 맛집·카페에 `라이더 추천`이라는 이름을 붙이면 바이크 친화성을 검증한 장소처럼 보일 수
있다. 라이더가 함께 가볼 일반 목적지를 나누는 참여는 열어 두되 모토맵 등록 장소와 의미를
명확히 나눠야 한다.

### 결정

- 일반 장소 상세의 운영시간 아래, 리뷰 위에 벡터 공유 아이콘과 `라이더들과 공유하기` 버튼을
  둔다. 공유 후에는 벡터 체크 아이콘과 `라이더들과 공유 중`으로 바꾼다.
- 설명은 `바이크 특화 장소는 아니지만, 라이더가 함께 가볼 곳으로 공유할 수 있어요.`로 한다.
  공개된 공유 장소에는 같은 의미의 완료형 설명을 표시한다.
- 공유는 계정당 일반 장소별 하나이고 운영자 승인 없이 즉시 반영한다. 자유 문구·사진은 중복
  저장하지 않고 기존 리뷰를 사용한다.
- 기존 공식 제보 진입은 `바이크 특화 장소로 제보하기`로 명확히 이름을 바꾸고 공유 카드 아래에
  둔다. 공유 수만으로 공식 장소로 자동 승격하지 않는다.
- 지도에는 별도 `라이더 공유` 필터를 두고, 켰을 때만 공유된 일반 장소를 중립 마커로 표시한다.
  실제 지도 영역과 여유 영역 windowing은 MAP-020을 그대로 적용한다.
- 일반 장소가 등록 장소로 승격되면 공유 행은 보존하되 공유 레이어에서는 숨긴다. 나중에 등록
  해제되면 기존 공유가 다시 보인다.

### 검토한 대안과 시행착오

- 일반 장소 액션을 `추천하기`로 부르면 등록 장소 추천 및 바이크 특화 의미와 충돌하므로
  COMMUNITY-001의 명칭과 흐름을 대체한다.
- 공유 이유 선택을 먼저 요구하면 한 번의 간단한 의사 표시보다 참여 마찰이 커진다. 초기에는
  한 번의 공유 토글만 받고 맥락은 리뷰로 보완한다.
- 공유 장소를 기본 지도에 항상 노출하면 공식 등록 장소와 혼동되고 마커 밀도가 증가하므로
  명시적으로 켜는 별도 레이어를 유지한다.

### 영향과 재검토 조건

공유 장소는 검색 TOP 5에 포함하지 않는다. 공유 레이어에서 마커가 250개를 넘거나 입력 지연이
확인되면 클러스터보다 거리·공유 수·최근성 기반 상한을 먼저 검토한다. 스팸이 확인되면 계정
신뢰도와 신고 흐름을 추가하되 운영자 승인형 제보로 되돌리지는 않는다.

## COMMUNITY-005 — 일반 장소 행동은 추천으로 표현하고 공식 추천과 분리한다

- 날짜: 2026-08-24
- 상태: 대체됨(COMMUNITY-006)
- 관련 구현: `public.general_place_shares`, `components/map/TempPlaceSheet.tsx`,
  `components/map/MapHome.tsx`

### 배경

`라이더들과 공유하기`는 장소 링크를 외부로 보내는 공유 버튼과 의미가 겹치고, 사용자가 누르면
무엇이 달라지는지 바로 이해하기 어려웠다. 반면 일반 장소를 다른 라이더에게 권한다는 행동 자체는
`추천`이 가장 자연스럽다. 다만 등록 장소의 명시적 추천 및 바이크 특화 검증과 혼동되는 경계는
계속 지켜야 한다.

### 결정

- 일반 장소 상세의 행동은 벡터 체크 아이콘과 `장소 추천하기`로 표시한다. 선택 후에는 채워진
  체크 아이콘과 `장소 추천 완료`로 바꾸고, 추천 수는 제목 바로 옆에 표시한다.
- 설명은 `바이크 특화 장소는 아니지만, 라이더가 가볼 만한 곳으로 추천해요.`로 고정해 일반
  추천이 바이크 특화 인증을 뜻하지 않음을 같은 카드 안에서 밝힌다.
- 내부 데이터는 `general_place_shares`를 그대로 사용한다. 일반 장소 추천은 등록 장소의
  `place_recommendations`로 합치지 않으며 `라이더 추천 TOP 5`에도 포함하지 않는다.
- 지도 필터와 분석 이벤트는 일반 장소가 모토맵 검증 장소와 구분되는 별도 발견 레이어라는 의미를
  보존하기 위해 `라이더 공유` 명칭과 기존 계약을 유지한다.
- 계정당 일반 장소별 하나, 운영자 승인 없이 즉시 반영, 공식 장소로 자동 승격하지 않는 정책은
  COMMUNITY-004에서 그대로 승계한다.
- 체크 상태와 추천 수가 낙관적으로 즉시 바뀌므로 성공 토스트를 중복 표시하지 않는다. 로그인
  필요와 서버 반영 실패처럼 사용자가 조치해야 하는 상황만 상단 피드백으로 알린다.

### 검토한 대안과 시행착오

- `라이더 추천`을 카드 제목이나 지도 필터명으로 쓰면 장소 자체가 바이크 특화 검증을 받은 것처럼
  보일 수 있어 사용하지 않는다. 행동은 중립적인 `장소 추천`으로 한정하고 설명으로 범위를 밝힌다.
- 데이터와 이벤트까지 추천으로 즉시 개명하면 기존 OTA 클라이언트·집계·RPC 계약을 불필요하게
  깨뜨리므로 사용자 문구만 바꾸고 도메인 신호는 유지한다.

### 영향과 재검토 조건

사용자가 설명을 읽지 않고도 일반 장소를 공식 등록 장소로 오해하는 사례가 관찰되면 카드에
`일반 장소` 라벨을 추가하거나 행동 명칭을 다시 검토한다. 일반 장소 추천을 별도 랭킹에 포함할
때에도 등록 장소 TOP 5와 같은 목록으로 합치지 않는다.

## COMMUNITY-006 — 등록 장소는 좋아요, 일반 장소는 추천으로 구분한다

- 날짜: 2026-08-24
- 상태: 대체됨(COMMUNITY-007)
- 관련 구현: `components/place/RiderPlaceFacts.tsx`, `app/search.tsx`,
  `components/map/CategoryFilter.tsx`, `public.place_recommendations`,
  `public.general_place_shares`

### 배경

등록 장소와 일반 장소가 모두 `추천`을 받으면 같은 신뢰 수준의 장소처럼 보이고, 정작 바이크
특화 검증을 거치지 않은 일반 장소를 라이더가 권한다는 기능의 의미가 흐려진다. 등록 장소는 이미
운영 기준을 통과했으므로 사용자의 추가 신호는 승인이나 추천보다 가벼운 호감 리액션이 자연스럽다.

### 결정

- 등록 장소의 기존 추천 버튼을 벡터 따봉 아이콘과 `좋아요 · N`으로 바꾼다. 미선택은 외곽선,
  선택은 채운 아이콘과 강조 배경을 사용하고 낙관적 반영·오류 원복 계약은 유지한다.
- 검색의 등록 장소 순위는 `라이더 인기 TOP 5`로 표시하고 행의 집계도 `좋아요 N`으로 쓴다.
  후보와 동률 정렬 기준은 COMMUNITY-003의 기존 알고리즘을 그대로 사용한다.
- 일반 장소의 `장소 추천하기`와 체크 아이콘은 유지한다. 지도 필터는 `추천 장소`로 표시하며
  이 필터에는 바이크 특화 등록 장소를 합치지 않고 일반 추천 장소만 추가로 보여준다.
- 기존 `place_recommendations` 행은 사용자가 남긴 긍정 반응이므로 좋아요로 그대로 승계한다.
  `general_place_shares`와 합치거나 서로 변환하지 않는다.
- 구버전 OTA, RPC, 대시보드의 연속성을 위해 테이블·RPC·React Query 키·분석 이벤트의 기존
  recommendation/share 이름은 유지한다. 사용자 문구와 분석 문서에서 현재 의미를 명시한다.
- 좋아요와 일반 장소 추천 모두 상태·집계 변화가 성공 피드백이므로 성공 토스트를 띄우지 않고,
  로그인 필요와 실패만 알린다.

### 검토한 대안과 시행착오

- 하나의 `라이더 추천` 필터에 등록 장소와 일반 장소를 함께 넣으면 중립 마커를 사용해도 모두
  모토맵이 검증했거나 같은 기준으로 추천받은 것처럼 보이므로 채택하지 않는다.
- 기존 추천 데이터를 초기화하면 이미 참여한 사용자의 의사와 집계가 사라진다. 추천과 좋아요는
  모두 명시적인 긍정 반응이므로 데이터는 보존하고 표현만 가볍게 바꾼다.
- DB와 이벤트를 즉시 `like`로 개명하면 1.2.7 구버전과 분석 시계열을 깨뜨리는 비용에 비해
  사용자 가치가 없으므로 호환 이름을 유지한다.

### 영향과 재검토 조건

좋아요는 등록 승인 근거나 객관적인 라이더 편의 정보로 해석하지 않는다. 인기 순위가 특정 지역의
기존 장소에 고착되면 기간별 좋아요나 지역별 인기 목록을 검토한다. 일반 추천 장소와 등록 장소를
한 화면에서 함께 발견시킬 필요가 커져도 하나의 필터로 합치기보다 마커 범례나 별도 섹션을 먼저
검토한다.

## COMMUNITY-007 — 데이터가 충분해질 때까지 등록 장소 인기 순위를 만들지 않는다

- 날짜: 2026-08-24
- 상태: 활성
- 관련 구현: `components/place/RiderPlaceFacts.tsx`, `app/search.tsx`,
  `public.place_recommendations`

### 배경

등록 장소의 좋아요를 없앤 뒤 즐겨찾기나 라이더 제공 정보를 대신 사용해 `인기 TOP 5`를 유지할지
검토했다. 운영 데이터에는 활성 등록 장소 120곳 중 즐겨찾기가 2개 계정·6곳에 각 1건씩만 있었고,
라이더 제공 정보 40건도 한 계정이 17곳에 여러 항목을 확인한 기록이었다. 즐겨찾기로 다섯 곳을
고르면 모두 1표인 장소를 임의로 줄 세우게 되고, 라이더 정보 항목 수로 고르면 인기보다 정보를
많이 입력한 장소 순위가 된다.

### 결정

- 등록 장소 상세에서 COMMUNITY-006의 좋아요 버튼을 제거하고 검색 첫 화면의
  `라이더 인기 TOP 5`도 표시하지 않는다.
- 즐겨찾기는 개인이 다시 찾으려는 저장 의도, 라이더 제공 정보는 주차·진입 같은 사실 확인으로
  해석한다. 둘을 인기 점수로 합치거나 서로 대신 사용하지 않는다.
- 1.2.7은 아직 TestFlight에만 있고 App Store 운영 버전 1.2.6은 이 API를 사용하지 않으므로,
  `place_recommendations` 행·테이블·RPC와 `places`의 전용 집계 컬럼을 마이그레이션으로 제거한다.
  일반 장소의 `general_place_shares`는 별도 계약이므로 변경하지 않는다.
- 일반 장소의 `장소 추천하기`는 다른 라이더에게 소개하려는 명시적 의사이므로 그대로 유지한다.
  이 신호도 등록 장소 순위나 바이크 특화 승인 근거에는 합치지 않는다.

### 검토한 대안과 시행착오

- 즐겨찾기 수는 라이더 정보보다 인기와 가깝지만 현재는 전부 1표라 TOP 5의 순서와 경계가
  설명되지 않는다. 개인 저장을 공개 추천으로 과장할 위험도 있어 지금은 사용하지 않는다.
- 라이더 제공 정보는 한 계정이 장소마다 여러 사실 코드를 남길 수 있어 원시 행 수가 풍부한
  장소에 유리하다. 고유 제공자 수로 바꿔도 현재 모두 한 명이라 순위 신호가 되지 않는다.
- 두 신호를 가중 합산하면 데이터 희소성을 해결하지 못하면서 사용자에게 설명하기 어려운 점수만
  생기므로 채택하지 않는다.
- 공개 배포된 구버전이 사용한다고 가정해 좋아요 스키마를 호환용으로 남기는 방안도 검토했지만,
  1.2.7은 TestFlight 전용이고 운영 버전 1.2.6에는 해당 호출이 없어 불필요한 잔존 스키마가 된다.

### 영향과 재검토 조건

즐겨찾기는 순위를 노출하지 않아도 계속 축적한다. 서로 다른 실제 계정 3명 이상이 저장한 등록
장소가 최소 5곳 생기고 상위권이 전부 같은 수로 묶이지 않을 때 공개 목록을 다시 검토한다. 그때도
즐겨찾기만 쓴다면 `인기`보다 측정 기준을 정확히 드러내는 `많이 저장한 장소`로 표시한다. 라이더
제공 정보는 장소 상세의 정보와 신뢰 표시로만 사용한다.

## COMMUNITY-008 — 주유소는 일반 장소 추천 대상에서 제외한다

- 날짜: 2026-08-24
- 상태: 활성
- 관련 구현: `components/map/TempPlaceSheet.tsx`, `lib/api/gasStations.ts`

주유소 일반 장소 상세에서는 `장소 추천하기` 카드와 추천 수를 표시하지 않는다. 주유소는 추천을
통해 발견시키는 일반 목적지보다 유가·위치·길안내가 핵심인 실용 레이어이고, 이미 상세에서도
바이크 특화 장소 제보 진입을 숨기고 있다. 기존 추천 데이터의 의미를 임의로 삭제하지는 않되 새로
추천하거나 취소하는 UI는 제공하지 않는다. 향후 라이더가 선호하는 주유소 신호가 필요해지면 일반
장소 추천을 재사용하지 않고 고급유·접근성 같은 주유소 전용 정보 모델로 검토한다.
