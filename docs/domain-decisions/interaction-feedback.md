# 공통 아이콘·터치 피드백

사용자가 누를 수 있는 요소를 즉시 알아차리고, 같은 행동을 화면마다 같은 시각 언어로
이해하도록 하는 앱 공통 상호작용 결정이다.

관련 구현:

- `app/course/[id].tsx`
- `components/map/PlaceBottomSheet.tsx`
- `components/map/TempPlaceSheet.tsx`
- `components/map/WeatherFab.tsx`
- `components/map/MapHome.tsx`

## 먼저 확인할 활성 원칙

1. 공유 행동은 `Ionicons`의 `share-outline` 아이콘으로 통일한다. 화면 성격에 따라 크기와
   색은 달라도 아이콘 모양은 바꾸지 않는다.
2. 사용자가 누르는 액션은 터치하는 동안 즉시 시각 피드백을 보여준다. `TouchableOpacity`의
   기본 투명도 변화도 유효한 피드백이며, `Pressable`은 눌림 스타일이나 애니메이션을 명시한다.
3. 지도 위 플로팅 버튼처럼 독립된 작은 컨트롤은 탭 아이콘과 같은 짧은 timing 축소 피드백을
   우선하되 손을 떼는 순간 원래 크기로 즉시 복귀한다. 카드·텍스트 버튼은 투명도 또는 테두리
   변화로 레이아웃을 움직이지 않게 한다.
   네이티브 Glass 버튼은 INTERACTION-015의 UIKit 상호작용을 쓰며 JS 축소·오버슛을 겹치지 않는다.
4. 앱의 직접 햅틱 기능은 제거했다. 탭·버튼의 시각 피드백은 유지한다(INTERACTION-030).
5. 즐겨찾기·저장·읽음처럼 되돌릴 수 있고 최종 상태가 명확한 서버 액션은 낙관적으로 반영한다.
   서버 명령은 현재 상태를 뒤집지 않고 원하는 최종 상태를 멱등적으로 설정하며, 실패하면 모든
   관련 캐시를 원상복구하고 사용자에게 알린다.
6. 화면·모달·카드를 닫는 X는 글리프 여백이 없는 공용 `CloseIcon`으로 통일한다.
   검색어나 입력값을 비우는 `close-circle`은 닫기와 다른 액션이므로 기존 아이콘을 유지한다.
7. 장소 상세의 전체 확장 헤더에서는 뒤로가기 `chevron-back`의 실제 선 영역이 주변 액션보다
   작아 보이지 않도록 28px로 표시한다. 버튼의 44px 터치 영역은 변경하지 않는다.
8. 장소 즐겨찾기는 등록 여부와 확장 상태에 관계없이 같은 낙관적 피드백을 사용한다. 추가할
   때만 별이 한 번 커졌다 돌아오며, 활성 별은 항상 `semantic.star` 노란색을 유지한다.
9. 전체화면 사진은 사진 자체를 탭해 닫지 않는다. X 또는 아래로 스와이프할 때만 닫고,
   두 손가락 핀치로 1~4배 확대·축소한다. 확대 중 한 손가락 이동은 사진 탐색에 사용하며
   페이지 이동·닫기 제스처로 해석하지 않는다.
10. 시스템 컨트롤의 OS 기본 피드백과 앱이 직접 재생하는 햅틱을 구분한다.
    모토맵의 진동 호출·설정 스위치·저장/로드는 제거하며 시스템 전역 설정은 바꾸지 않는다.
11. 아이콘만 있는 버튼은 `accessibilityLabel`과 `accessibilityRole="button"`을 둔다. `Pressable`을
    다른 `Pressable` 안에 중첩하지 않는다(바깥이 하나의 접근성 요소로 묶여 안쪽 버튼이
    스크린리더에서 사라진다). 터치 영역은 가능하면 44pt 이상으로 하고, 이웃 버튼과 겹치게
    `hitSlop`을 늘리지 않는다(INTERACTION-010).

12. 새 아이콘은 의미가 맞는 기존 표준 라이브러리 원본을 우선 재사용한다. 기존 아이콘이 있는데
    새 SVG 도형을 직접 그리지 않는다(NAV-049). 하단 목적지처럼 사용자가 같은 도형을
    명시한 경우는 기존 화면 도형을 재사용한다(NAV-045/046).
13. iOS의 기본 탭은 시스템 NativeTabs로 제공한다. iOS 26 이상에서는 UIKit Liquid Glass를
    사용하며 JS 탭의 축소·오버슛 애니메이션을 덧씌우지 않는다. Android·웹은 기존 JS 탭을 유지한다.
14. 개별 조작 요소의 유리 표면은 공용 `GlassSurface`를 사용한다. native 모듈·API 가용성과
    투명도 줄이기를 확인하며, 미지원/확인 전에는 테마의 불투명 표면으로 대체한다(INTERACTION-014).

## INTERACTION-001 — 공유 아이콘과 눌림 상태를 앱 공통 규칙으로 둔다

- 날짜: 2026-08-23
- 상태: 대체됨(INTERACTION-002)
- 관련 구현: `app/course/[id].tsx`, `app/my-rides.tsx`,
  `components/profile/RiderShareCard.tsx`, `components/map/`

### 배경

코스·주행기록은 `share-outline`을 사용했지만 장소 상세은 서로 다른 계열의 `share-2`를 사용해
같은 행동이 다른 기능처럼 보였다. 또한 `Pressable`에 눌림 상태가 없는 지도 날씨 버튼은 터치가
전달됐는지 시트가 열릴 때까지 알기 어려웠다.

### 결정

공유 액션은 모두 `Ionicons share-outline`으로 통일한다. 새 공유 진입점을 추가할 때도 같은
아이콘을 사용하고 접근성 라벨에 공유 대상을 명시한다.

일반 액션은 터치 중 투명도·색·테두리 중 하나 이상을 바꾸고, 지도 날씨 같은 플로팅 버튼은
탭 아이콘과 같은 timing 시퀀스(누르는 동안 82%, 뗀 뒤 한 번만 복귀)로 반응한다. 잔진동이
남는 물리 스프링은 쓰지 않는다. 이미 눌림 피드백을 제공하는
`TouchableOpacity`나 상태별 스타일이 있는 `Pressable`에는 중복 애니메이션을 얹지 않는다.
배경 닫기 영역이나 이벤트 전파만 막는 컨테이너처럼 독립 버튼으로 보이지 않는 요소는 예외다.

### 검토한 대안과 시행착오

모든 액션에 햅틱만 추가하면 햅틱을 끈 사용자와 기기에서 피드백이 사라지고, 모든 버튼에
스프링을 적용하면 손을 뗀 뒤에도 잔진동이 남아 반응이 늦게 끝난다. 컨트롤 형태에 맞춰 축소와 색상
피드백을 나누되, 반응이 있다는 원칙만 공통으로 유지한다.

### 영향과 재검토 조건

새로운 터치 액션을 만들 때 기본 피드백과 접근성 역할·라벨을 함께 확인한다. 시스템의 동작
줄이기 설정에서 timing 효과가 불편하거나 지도 조작 성능에 영향이 확인되면 플로팅 버튼도 투명도
피드백으로 낮춘다. 아이콘 라이브러리를 교체할 때는 공유 아이콘을 화면별로 다시 갈라놓지 않는다.

## INTERACTION-002 — 눌림 축소는 터치 중에만 유지한다

- 날짜: 2026-08-23
- 상태: 활성
- 관련 구현: `components/map/WeatherFab.tsx`

### 배경

터치를 뗀 뒤 106%까지 커졌다가 돌아오는 timing 시퀀스도 작은 플로팅 버튼에서는 눌림보다 후속
애니메이션이 더 강하게 느껴졌다. 사용자가 원하는 피드백은 터치 중 눌렸다는 표시이지 탭 완료 후의
별도 강조가 아니다.

### 결정

지도 날씨 버튼은 누르는 동안만 82%로 줄어들고, 손을 떼거나 터치가 취소되면 진행 중인 축소를
즉시 중단하고 100% 크기로 복귀한다. 오버슈트·스프링·복귀 timing 애니메이션은 사용하지 않는다.
공유 아이콘 통일과 일반 버튼의 투명도 피드백 원칙은 그대로 유지한다.

### 영향과 재검토 조건

새 플로팅 버튼도 터치 중 상태와 해제 상태를 명확히 분리한다. 시스템 동작 줄이기 여부와 관계없이
손을 뗀 뒤 애니메이션이 남지 않아야 한다.

## INTERACTION-003 — 되돌릴 수 있는 서버 액션은 최종 상태를 먼저 보여준다

- 날짜: 2026-08-23
- 상태: 활성
- 관련 구현: `hooks/useFavorites.ts`, `hooks/useCourseLibrary.ts`, `hooks/useNotifications.ts`,
  `hooks/useBlocks.ts`, 리뷰·바이크 관련 mutation

### 배경

즐겨찾기처럼 결과가 별 채움 하나로 명확한 액션도 서버 조회와 쓰기, 재조회가 끝날 때까지 기존
상태를 보여주면 터치 피드백과 실제 상태 변화 사이에 지연이 생긴다. 특히 일반 장소 즐겨찾기는
일반 장소 식별자 생성까지 여러 왕복이 필요해 등록 장소보다 늦게 반응했다.

### 결정

- 사용자가 요청한 최종 상태가 명확하고 실패 시 안전하게 되돌릴 수 있는 액션은 관련 React Query
  캐시 또는 로컬 상태를 먼저 갱신한다.
- 서버 API는 `toggle`처럼 읽은 현재값의 반대를 쓰지 않고 `on/off` 같은 목표 상태를 받는 멱등
  명령으로 만든다. 동일 요청의 재전송과 중복 탭이 상태를 다시 뒤집어서는 안 된다.
- mutation 시작 전에 영향받는 캐시를 취소하고 스냅샷을 보존한다. 실패하면 전체 스냅샷을 복구해
  오류를 알리고, 완료 뒤에는 서버 기준으로 재검증한다.
- 서버 생성 ID가 필요한 새 행은 화면 판정에 쓰는 안정적인 장소 식별자나 임시 ID로 먼저 나타내고,
  재조회 결과로 실제 행과 교체한다.
- 분석 이벤트는 낙관적 화면 변경 시점이 아니라 서버 성공 뒤 기록해 실패한 조작을 성공으로 세지
  않는다.

### 검토한 대안과 시행착오

모든 액션을 서버 확정 뒤에만 바꾸면 데이터는 단순하지만 네트워크 지연이 그대로 UX 지연이 된다.
반대로 제보·신고·계정 삭제처럼 승인·검증 결과가 중요한 동작까지 성공한 것처럼 먼저 보이면 실패
복구가 혼란스럽다. 따라서 즐겨찾기·저장·읽음·차단·수정처럼 되돌릴 수 있는 동작에만 적용한다.

### 영향과 재검토 조건

즐겨찾기·코스 저장·알림 읽음·차단·리뷰 수정/삭제·활성 바이크 변경은 이 계약을 따른다. 장소·코스·
위험 제보, 신고, 계정·인증, 파일 업로드, 바이크 삭제, 완주·도착 기록은 서버 확정을 기다린다.
낙관적 상태와 서버 상태의 불일치가 반복되면 개별 화면에서 임시 처리를 늘리기보다 해당 쓰기를
원자 RPC로 올릴지 검토한다.

## INTERACTION-004 — 닫기 X는 Material Icons로 통일한다

- 날짜: 2026-08-23
- 상태: 대체됨(INTERACTION-005)
- 관련 구현: `app/`, `components/`의 닫기 액션

### 배경

`Ionicons close`는 지정한 px 크기가 다른 액션 아이콘과 같아도 글리프 내부 여백과 얇은
획 때문에 X가 더 작게 보였다. 장소 상세만 크기를 키우면 다른 닫기 액션과 다시
어긋난다.

### 결정

닫기를 의미하는 모든 X는 같은 지정 크기에서도 획과 바운딩 영역이 더 선명한
`MaterialIcons close`를 사용한다. 기존 아이콘 px와 터치 영역은 변경하지 않아 레이아웃과
접근성 범위를 유지한다. `Ionicons close-circle`은 검색·입력값 초기화 전용으로 남긴다.

### 영향과 재검토 조건

새 닫기 액션은 화면별 아이콘 라이브러리를 따로 고르지 않는다. 전체 아이콘 체계를
교체하거나 플랫폼 기본 닫기 컨트롤로 이전할 때 함께 재검토한다.

## INTERACTION-005 — 실제 선 길이가 긴 Font Awesome X를 사용한다

- 날짜: 2026-08-23
- 상태: 대체됨(INTERACTION-006)
- 관련 구현: `app/`, `components/`의 닫기 액션

### 배경

INTERACTION-004에서 `MaterialIcons close`로 교체했지만, 실제 X 바운딩 박스는 폰트
em 크기의 약 58%라 지정 크기보다 선이 여전히 짧게 보였다. 아이콘 px만 늘리면 화면별
크기 규칙을 다시 조절해야 한다.

### 결정

닫기 X는 실제 바운딩 박스가 em의 약 66%를 채우는 `FontAwesome times`로 통일한다.
`MaterialIcons close`보다 같은 px에서 선 길이가 약 14% 길어져, 터치 영역·레이아웃·기존
아이콘 px를 바꾸지 않고도 시각 크기를 키운다. 입력값 초기화용 `close-circle`은 계속 예외다.

### 검토한 대안과 시행착오

- `MaterialIcons close`는 Ionicons보다 나았지만 실기기에서도 여백이 크게 느껴져 대체했다.
- 두 개의 회전한 `View`로 X를 직접 그리면 바운딩을 완전히 제어할 수 있지만, 작은
  px에서 플랫폼별 안티앨리어싱이 달라질 수 있어 아이콘 폰트를 유지한다.

### 영향과 재검토 조건

시각 크기가 아직도 부족하거나 획이 과하게 느껴지면 개별 px를 늘리지 말고 공통
`CloseIcon`을 SVG로 정의해 실제 path 크기를 고정하는 방식을 재검토한다.

## INTERACTION-006 — 글리프 대신 여백 없는 선형 X를 직접 그린다

- 날짜: 2026-08-23
- 상태: 활성
- 관련 구현: `components/ui/CloseIcon.tsx`, `app/`, `components/`의 닫기 액션

### 배경

`FontAwesome times`는 Material Icons보다 선이 길었지만 여전히 폰트 em 내부 여백이 남고,
획도 네이버 지도처럼 길고 균형 잡힌 선형 X보다 굵게 보였다. 지정 px를 키우는 방식으로는
화면마다 다른 아이콘 크기와 버튼 레이아웃을 함께 조절해야 한다.

### 결정

닫기 X는 공용 `CloseIcon`이 두 개의 대각선을 직접 그리도록 한다. 대각선의 외곽 바운딩은

### 검토한 대안과 시행착오

  여전히 짧게 보였다.

## INTERACTION-009 — 앱 햅틱 설정과 시스템 햅틱 설정을 구분한다

- Core Haptics의 `supportsHaptics`는 하드웨어 지원 여부일 뿐 사용자의 시스템 토글 상태가 아니다.
- 앱이 시스템 설정을 직접 바꾸는 방식은 사용자 선택을 침해하며 공개 API도 제공되지 않는다.

### 영향과 재검토 조건

Apple이 시스템 햅틱 상태 조회나 해당 설정 화면으로의 공식 딥링크를 제공하면 다시 검토한다.

## INTERACTION-012 — iOS 탭을 UIKit Liquid Glass로 전환한다

- 날짜: 2026-11-02
- 상태: 사용자 승인 / 소스 구현, 새 바이너리·실기기 QA 전
- 관련: `app/(tabs)/_layout.tsx`, `components/navigation/NativeTabScreen.tsx`,
  `components/navigation/NotificationBell.tsx`, `tests/nativeTabs.test.ts`

### 결정과 경계

설치된 Expo SDK 57의 `expo-router/unstable-native-tabs`를 사용한다. iOS 26 이상은 시스템의
Liquid Glass, 이전 iOS는 시스템 기본 탭 외형이다. 새 의존성·BlurView·고정 탭 너비/높이·임의
OS 버전/빌드 번호 게이트를 추가하지 않는다. Android·웹은 기존 JS 탭을 유지한다.
시스템 최소화는 `never`로 두고 iPad도 하단 탭을 유지한다. 지도·탐색·제보·내 정보의 URL과
params, 지도 상세 포커스 helper는 그대로다. 지도 재선택으로 카메라/시트를 초기화하지 않는다.

아이콘은 SF Symbols의 기본/선택 쌍이다. UIKit이 눌림·선택 효과를 그리므로 기존 Reanimated
탭 오버슛을 iOS에 중복 적용하지 않는다. 내 정보 상단의 로그인 전용 알림 버튼과 탭 미읽음
배지를 보존한다. NativeTabs에는 헤더 API가 없어 탐색·제보·내 정보에는 48pt 이상 공용 헤더를
제공하고 지도에는 새 헤더를 추가하지 않는다.

NativeTabs는 eager mount하므로 첫 포커스까지 화면 본체를 미루며, 한 번 연 뒤에는 포커스를
잃어도 본체를 유지한다. 폼·목록·지도 상태를 탭 이동마다 없애는 `focused && <Screen />`는 쓰지 않는다.

### 안전 영역과 지도

자동 ScrollView inset 조정을 끄고 공식 권장 `react-native-screens/experimental` SafeAreaView로
실제 native bottom/좌우 영역을 확보한다. 지도와 시트·FAB를 같은 가용 프레임에 두며, 지도 카메라
보정도 기기 전체 높이 대신 MapHome의 실측 onLayout 높이를 쓴다. 탭바의 공개 높이 hook은 없으므로
JS 탭 전용 `useBottomTabBarHeight`를 호출하거나 기기별 높이를 추정하지 않는다.

NativeTabs가 추가하는 tab-local SafeAreaProvider 때문에 전체화면 Modal의 하단 여백에 탭 높이가
섞이지 않도록, 탭 레이아웃에서 읽은 기존 기기 inset을 자식에게 이어준다. 화면 전체를 바텀
safe frame 안에 두던 배치는 INTERACTION-013으로 대체됐다. 탭바 높이 hook을 호출하거나
기기별 높이를 상수로 추정하지 않는 경계는 유지한다.

### 검증과 전달

대역 검사로 iOS/Android·웹 분기, 4개 경로, 배지·알림 진입, 첫 방문 지연·재방문 유지, 헤더와
기기 inset 전달, 지도 실측 높이 연결을 확인한다. 이는 UIKit 실제 모양·Glass 투명도·VoiceOver·
작은 화면/가로 화면·큰 글자·키보드·전체화면 사진/지도 선택 모달 검증을 대체하지 않는다.
새 production/TestFlight 바이너리에서 이 항목을 확인한 뒤 배포한다. 기존 67번에서 OTA가
가능하다고 단정하거나 미검증 소스를 바로 OTA하지 않는다. native bridge38/API1·runtime1.2.11은
그대로이며 네이티브 소스·SDK 버전·서버 계약을 변경하지 않는다.

[Native tabs의 safe area·lazy loading](https://docs.expo.dev/router/advanced/native-tabs/).

### 결정

탭 콘텐츠는 화면 맨 아래까지 그린다. iOS는 시스템 Liquid Glass 탭을 그대로 두고, 화면을

## INTERACTION-018 — 공용 clear 재질과 풀 확장 전용 장소 Glass

- 날짜: 2026-11-04
- 상태: 활성 / 로컬 외형 검증 후속

네이티브 패치를 추가하지 않으며, 선택 배경까지 바뀐 것으로 보고하지 않는다. 모토맵의
실제 기기 외형은 별도로 확인한다. 네이티브·의존성·브리지 계약 변경은 없다.

다크 카테고리 칩의 차콜 배경·밝은 테두리·부드러운 선택 tint는 제안 단계다. 사용자 선택 전에는
기존 카테고리 색을 바꾸지 않는다.

공식 근거: [Apple selectionIndicatorTintColor](https://developer.apple.com/documentation/uikit/uitabbarappearance/selectionindicatortintcolor),
[Expo NativeTabs 외형](https://docs.expo.dev/tutorial/add-navigation/).

## INTERACTION-019 — iOS 하단 탭은 본문과 독립된 다크 외형으로 통일한다

- 날짜: 2026-11-04
- 상태: 대체됨(INTERACTION-020) — 실제 외형 사용자 거절, 본문 테마 연동으로 복원
- 대체: INTERACTION-017·018의 본문 테마를 따르는 iOS 탭 외형·라이트 파랑 선택색

사용자는 라이트의 활성 탭도 다크와 같은 모습으로 요청했다. 별도 UIKit iOS27 테스트에서
흰 아이콘/글자만 넣으면 밝은 회색 선택 배경에 묻히는 것을 확인해, 두 대안을 제시했다.
사용자가 **탭 바 전체를 다크 외형으로 통일**하는 안을 선택했다.

iOS 각 trigger의 탭 바 전용 `experimental_userInterfaceStyle`을 `dark`로 고정하고
탭 색도 Colors.dark를 사용한다. host `colorScheme`은 본문 테마를 유지한다. host까지
dark로 고정하면 전체 자식 컨트롤러의 UIKit trait까지 바뀌기 때문이다.
활성 아이콘/글자는 `#FAFAFA`, 비활성은
다크 보조 색이다. 본문 useColorScheme·테마 저장·지도/화면 배경·StatusBar 선택은 바꾸지 않는다.
Android/웹의 JS 탭은 기존 테마별 색을 유지한다. 네이티브 탭의 public 외형 옵션만 사용하며
선택 pill 조작용 native patch·의존성·계약 변경은 없다.
탭 바 전용 스타일 override가 없는 iOS26 미만에서는 dark 배경/blur를 명시해 흰 선택색이
밝은 기본 탭 배경에 묻히지 않도록 한다. scroll-edge 투명화도 이 구버전에서만 꺼서
짧은 목록/스크롤 끝에서도 dark 배경을 유지한다. iOS26 이상은 배경·blur를 강제하지 않는다.

### Glass 재질 후속 제안 (미적용)

Apple 가이드는 regular의 배경 대비 적응을 기본으로 권장하고 clear는 미디어 위의 밝고
두꺼운 콘텐츠·배경 dimming을 마련한 경우로 제한한다. 같은 조작 그룹에 두 재질을 섞지 않는다.
현재 강제 흰 tint를 제거한 regular를 지도/일반 조작부 공통 후보로 제안하며, clear는 사진 등
별도 미디어 맥락에서 검토한다. 이는 제안으로, 현재 공통 clear 기본값을 바꾸지 않는다.

## INTERACTION-020 — 탭은 테마별 네이티브 외형, 지도 세 조작부는 무틴트 regular

- 날짜: 2026-11-04
- 상태: 활성 / 사용자 선택

## INTERACTION-029 — 네이티브 선택 재전달과 필터 재생성으로 생기는 흔들림을 줄인다
