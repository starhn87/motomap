# 레이아웃 안정성과 로딩 UI

React Native 앱에서 비동기 데이터가 들어올 때 콘텐츠가 갑자기 밀리거나 버튼 크기가 바뀌는
현상을 줄이기 위한 결정 기록이다. 웹의 CLS 수치를 직접 측정하는 문서는 아니지만 사용자가
느끼는 시각적 이동을 같은 문제로 다룬다.

관련 구현:

- `components/ui/Skeleton.tsx`
- `components/map/PlaceBottomSheet.tsx`, `components/map/TempPlaceSheet.tsx`
- `components/review/ReviewList.tsx`, `components/map/NearbyPlaces.tsx`
- 비동기 목록과 상세 화면의 초기 로딩 UI

## 먼저 확인할 활성 원칙

1. 화면의 제목·주소·주요 액션처럼 처음부터 아는 정보는 즉시 그린다. 부가 데이터 때문에 전체
   화면을 늦게 열지 않는다.
2. 초기 데이터가 화면 구조를 결정한다면 중앙 스피너 대신 최종 카드·행·지도와 크기가 비슷한
   스켈레톤을 사용한다.
3. 영업시간, 사진, 근처 장소, 리뷰처럼 나중에 도착하는 섹션은 최종 위치에 로딩 슬롯을 둔다.
   이미 보인 콘텐츠 위에 아무 표시 없이 섹션을 끼워 넣지 않는다.
4. 버튼의 로딩 상태는 버튼 크기와 문구 폭을 유지한 채 내부에 스피너를 겹치거나 같은 크기의
   요소로 교체한다. 로딩 때문에 행의 너비나 높이가 바뀌지 않아야 한다.
5. 이미지와 지도는 로딩 전부터 `width`·`height` 또는 `aspectRatio`를 확정한다.
6. 임의의 큰 `minHeight`로 모든 상태를 고정하지 않는다. 큰글자 모드에서 잘리거나 데이터가 없는
   화면에 빈 공간이 남을 수 있다. 구조가 항상 존재하는 카드와 액션에만 최소 높이를 사용한다.
7. 새로고침과 추가 페이지 조회는 기존 콘텐츠를 유지하고 해당 위치에만 진행 상태를 표시한다.
8. 스켈레톤은 실제 화면에 없는 장식이나 섹션을 과도하게 예고하지 않는다. 결과 유무를 알 수 없는
   선택 섹션은 로딩 중임이 분명한 자리만 잡고, 조회 완료 후 데이터가 없으면 제거한다.

## LAYOUT-001 — 콘텐츠 형태와 맞는 초기 로딩 상태를 사용한다

- 날짜: 2026-08-26
- 상태: 활성
- 관련 구현: `ReviewList.tsx`, `NearbyPlaces.tsx`, `PlaceBottomSheet.tsx`,
  `TempPlaceSheet.tsx`, `notifications.tsx`, `my-rides.tsx`, `riding/[id].tsx`,
  `search-results.tsx`, `edit-bike.tsx`, `edit-nickname.tsx`

### 배경

작은 중앙 스피너나 한 줄짜리 로더가 여러 카드와 긴 섹션으로 바뀌면 데이터가 정상적으로
도착해도 화면이 고장 난 것처럼 움직인다. 장소 상세에서는 영업시간·리뷰 사진·근처 장소·리뷰가
각각 다른 요청으로 도착해 아래 콘텐츠가 여러 번 밀릴 수 있었다. 반대로 추천 목적지와 내 바이크
카드는 최종 구조에 가까운 스켈레톤 또는 안정적인 최소 높이를 이미 사용해 큰 이동이 적었다.

### 결정

- 장소 상세의 비동기 영업시간, 사진, 근처 장소와 리뷰는 최종 섹션 위치에 형태가 맞는 로딩
  슬롯을 표시한다. 등록 장소와 일반 장소가 같은 원칙을 따른다.
- 알림, 주행 기록, 라이딩 추천 상세, 검색 결과, 내 차고와 닉네임 편집은 중앙 스피너 대신 실제
  헤더·카드·행·지도 구조를 닮은 스켈레톤을 사용한다.
- 데이터가 이미 있는 상태의 재조회는 전체 스켈레톤으로 되돌리지 않고 기존 콘텐츠를 유지한다.

### 검토한 대안과 시행착오

모든 선택 섹션의 최종 최대 높이를 영구 예약하면 물리적인 이동은 줄지만 사진·리뷰·근처 장소가
없는 곳에 큰 빈 공간이 남는다. 모든 요청이 끝날 때까지 바텀시트를 열지 않으면 구조는 안정적이어도
마커 탭 반응이 늦어진다. 따라서 기본 장소 정보와 액션은 즉시 보여주고, 비동기 부가 섹션만
스켈레톤으로 예고한다.

### 영향과 재검토 조건

스켈레톤과 실제 콘텐츠의 평균 높이 차이가 반복적으로 체감되면 카드별 실측 높이를 바탕으로
형태를 조정한다. 선택 섹션이 대부분 빈 데이터라 로딩 후 위로 접히는 이동이 더 거슬리면, 해당
섹션을 영구 표시하는 대신 화면 아래쪽으로 순서를 바꾸거나 조회를 상위 쿼리에 합치는 방식을
검토한다. 큰글자 모드와 로그인·비로그인, 데이터 있음·없음, 느린 네트워크를 함께 확인한다.
