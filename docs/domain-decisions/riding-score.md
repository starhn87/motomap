# 라이딩 습관 리포트와 점수

관련 기록: [경로 기록·라이딩 지도](ride-history.md), [길안내](navigation.md),
[위치정보 동의·자료 관리](location-privacy.md).

## 상태와 용어

- 이 문서는 **설계 중**이다. SCORE-001의 제품 방향만 사용자와 합의했다.
  아래 평가 항목·데이터·화면 연결은 승인 전 제안이며 구현된 기능이나 활성 수집 정책이 아니다.
- **라이딩 습관 리포트**: 측정 가능한 주행 특성과 측정 범위를 본인에게 설명하는 결과다.
  사고 위험·운전 실력을 판정하거나 보험용 안전운전 인증을 제공하지 않는다.
- **라이딩 점수**: 검증된 항목만으로 산출할 향후 베타 지표다. 초기 리포트와 구분하며,
  현재 점수 공식·가중치·공개 시점은 확정하지 않았다.
- **측정 품질**: 관측 누락·위치/속도 신뢰도·연속성을 나타낸다. 라이더의 운전 성적이 아니다.
- **속도 변화 이벤트**: 유효한 연속 표본에서 확인한 가속·감속 후보 구간이다.
  급감속 후보라는 이유만으로 위험운전·잘못된 제동이라고 부르지 않는다.

## SCORE-001 — 개인 회고용 리포트를 검증한 뒤 점수 베타를 도입한다

- 날짜: 2026-10-16
- 상태: 활성(제품 방향 합의, 구현 전)
- 관련 예정 기능: 주행 후 개인 리포트, 라이딩 지도·개별 라이딩 상세

### 배경

이용자는 네이버 지도·티맵과 같은 점수 기능을 모토맵에도 도입할 수 있는지 요청했다.
자동차용 평가 기준을 바이크에 그대로 적용하거나 긴급 회피 제동을 일률적으로 감점하면,
실제 상황을 설명하지 못하고 바람직하지 않은 운전을 유도할 수 있다.
현재 장소 방문 기록만으로는 실제 이동 중 속도 변화나 주행 습관을 역산할 수 없다.

### 결정

1. 목적은 타인과의 경쟁이 아니라 본인의 라이딩 습관과 변화 추이를 돌아보는 것이다.
   초기 결과는 본인 전용이며 순위·보험 연계·안전한 라이더 인증은 범위에서 제외한다.
2. 데이터 품질 검증 → 주행 리포트 검증 → 라이딩 점수 베타 순서로 진행한다.
   리포트가 존재한다는 이유로 검증되지 않은 종합 점수를 먼저 붙이지 않는다.
3. 사고를 피하기 위한 급제동처럼 맥락이 필요한 행동을 관측값 하나만으로 잘못된 운전이라
   단정하지 않는다. 급감속을 무조건 감점하는 방식은 채택하지 않는다.
4. 점수 산출 근거가 부족한 주행은 억지로 점수를 만들지 않고 `측정 부족`으로 표시한다.
   이는 0점이나 무사고·만점의 의미가 아니다.

### 검토한 대안과 재검토 조건

출시 첫날부터 100점 지표·순위를 제공하면 이해하기 쉽지만 정확성과 행동 유도 위험을
검증하지 못하므로 제외했다. 개인 회고 범위에서도 도로·상황 차이를 설명하지 못하는 항목은
관찰 정보에 머물거나 제외한다. 경쟁·보험·공개 공유는 별도 설계 없이는 추가하지 않는다.

## 다음 합의용 제안 — 평가 항목과 라이딩 지도 연결

다음 항목은 **사용자 확인 대기**다. SCORE-001의 확정 결정과 혼동하지 않는다.

### 1. 무엇을 보여주고 무엇을 점수에서 제외할지

| 항목 | 초기 리포트 제안 | 향후 점수 반영 경계 |
| --- | --- | --- |
| 주행 규모 | 유효하게 측정된 거리·시간·이동 중 평균 속도, 측정 범위 | 거리·속도가 높다는 이유로 보상하지 않음 |
| 급가속 후보 | 유효 연속 구간의 횟수·측정 거리당 빈도, 파악 가능한 경우 발생 구간 | 우선 관찰만. 바이크·도로 조건과 오탐을 검증하기 전 감점하지 않음 |
| 급감속 후보 | 급가속과 분리 표시하며 상황을 단정하지 않음 | 초기 감점 제외. 위험 회피 제동·정상 정차를 구분하지 못하면 계속 제외 |
| 제한속도 초과 | 신뢰할 현재 도로 제한속도가 없으면 `미측정` | 정확한 현재 도로·제한속도·유효 구간이 확보된 뒤 별도 검증. 단속 카메라 값을 전 도로에 확장하지 않음 |
| 장시간 주행·정차 | 측정된 연속 주행과 정차 구간을 회고 정보로 표시 | 피로·휴식·위험 상태로 추정하거나 점수에 반영하지 않음 |
| 측정 품질 | 유효 측정 시간·누락 구간·제외 사유를 별도 표시 | 품질 부족은 점수 유보 사유이지 감점 요인이 아님 |

최고속도 순위·코너링/기울기 실력·경로 완주 경쟁·야간 주행 자체의 감점은 초기 범위에서 제외한다.
시내 신호가 많은 길과 한적한 도로의 이벤트 횟수를 단순 비교하지 않는다. 내 변화 추이도
측정 범위·조건이 비교 가능할 때만 참고용으로 보여주고, 빈도가 줄었다고 안전해졌다고 단정하지 않는다.
서로 다른 품질·평가 버전의 결과를 한 추이로 합쳐 향상·악화를 표시하지 않는다.

### 2. 측정 가능성과 품질 검증

- 설치된 KNSDK 공개 헤더에는 위치 갱신 콜백과 원본/매칭 위치의 속도·시각·신뢰도 등이 있다.
  현재 JS 브리지는 이 데이터를 전달하지 않는다. 헤더의 존재만으로 외부 저장·재가공 허용이나
  실주행 수신 품질이 검증된 것은 아니다.
- 근거: `KNGuidance.h`의 `guidance:didUpdateLocation:`, `KNGuide_Location.gpsOrigin/gpsMatched`,
  `KNGPSData.speed/timestamp/posTrust/speedTrust`. 설치 위치는
  `ios/Pods/KNSDK-UI/KNSDK.xcframework/ios-arm64/KNSDK.framework/Headers/`다.
  속도 단위는 이 헤더에서 km/h이며 Expo Location의 m/s와 변환 경계를 검증해야 한다.
- `KNSafety_Camera.speedLimit`은 단속 지점 정보다. `KNLocation.trafficSpd`는 교통정보 속도이며
  제한속도가 아니다. 현재 도로 전체의 제한속도·미확인 판별 수단은 아직 확보하지 못했다.
- RIDE-001의 지도용 약 20m/5초 표본·단순화 경로에서 급가감속을 계산하지 않는다.
  원시 관측을 기기에서 검증해 이벤트·요약을 먼저 만들고 지도용 단순화는 별도 처리한다.
  필요한 주기·필터·유효 거리/시간·이벤트 임계치는 실제 표본 검증 전 확정하지 않는다.
- GPS 점프·낮은 신뢰도·긴 공백·앱 비활성화 경계는 이벤트 계산에서 끊는다.
  누락을 0회 이벤트로 채우거나 두 구간을 이어 순간 가속으로 계산하지 않는다.
  측정되지 않은 거리·시간은 따로 구분하고 예정 거리로 실제 측정 범위를 부풀리지 않는다.
- 과속을 제외한 다른 항목도 설득력 있는 평가 근거를 얻지 못하면 리포트만 유지한다.
  기능 이름을 맞추기 위해 의미 없는 종합 점수를 만드는 것은 도입 조건이 아니다.

### 3. 라이딩 지도와의 연결 제안

같은 실제 길안내 세션을 기준으로 `경로 표현`과 `습관 요약`을 나누는 구조를 권한다.
경로 저장은 리포트 이용의 필수조건이 아니며, 두 기능을 위해 위치 센서를 중복 구독하지 않는다.

- **공통 세션**: 실제 안내 시작·사용자 종료·중단·누락 경계를 공유하고 바이크 스냅샷을 연결한다.
  과거 `place_rides`와 삭제된 `public.rides`에서 새 리포트·점수를 만들지 않는다.
- **지도 기록 ON**: 본인용 실제 경로·리플레이에 같은 세션의 리포트를 연결한다.
  개별 라이딩 상세에는 거리·시간 다음에 `라이딩 습관` 진입을 둔다.
  관측 이벤트는 리포트에서 원할 때 지도에 표시하고 기본 경로를 항상 경고색으로 물들이지 않는다.
  이벤트를 지도에 붙이려면 단순화 이후에도 유효한 시간·구간 대응을 보존해야 한다.
- **지도 기록 OFF / 리포트 ON**: 기기에서 순간 관측을 처리해 요약만 남기는 방식을 제안한다.
  경로·이벤트 좌표는 보존하지 않고, 지도 리플레이와 이벤트 지점 표시도 제공하지 않는다.
  새 요약의 기기 전용/본인 서버 동기화 여부와 보존기간은 아직 미정이다.
- **리포트 OFF / 지도 기록 ON**: 경로만 남기며 습관 분석 자료를 부수적으로 만들지 않는다.
  설정을 켰다고 과거 경로를 소급 분석하지 않는다.
- **둘 다 OFF**: 기존 길안내·방문 저장 동작을 유지하고 새 자료는 만들지 않는다.
  현재 위치 일시 중지·철회는 기능별 선택보다 우선한다.
- **기간·바이크 탐색**: 라이딩 지도에서 기간·바이크를 고르면 같은 범위의 리포트를 찾아볼 수 있다.
  집·회사 도착의 공개 장소 통계 제외와 본인용 실제 주행 회고는 구분한다(RIDE-002).
  경로 비보존 세션을 지도에 가짜 선으로 그리거나 지도 경로 거리와 전체 요약 거리를 혼동하지 않는다.

이는 RIDE-001의 확정 데이터 모델을 바꾸는 결정이 아니다. 경로 없는 세션·선택 기능·삭제 범위를
합의한 뒤 기존 계획을 후속 결정으로 동기화한다. 구현/테이블 추가는 현재 요청 범위가 아니다.

### 4. 이용 중 방해하지 않는 결과 경험

- 주행 중 점수·감점 애니메이션·리포트 팝업을 띄우지 않는다.
- 목적지 도달 뒤에도 SDK 안전운행 화면이 유지된다(NAV-001). `도착`을 곧바로 최종 세션 종료로
  가정하지 않으며, 안내 화면의 명시적 종료 후 비차단형 리포트 진입을 두는 안을 권한다.
  도착 이후 안전운행 구간의 측정 포함 여부는 별도 확인할 미결정 항목이다.
- 경로/리포트 저장·분석이 실패해도 길안내 종료·기존 장소 방문·리뷰 흐름을 막지 않는다.
  오프라인 재시도·중복 종료·강제 종료 복구는 동일 세션에 중복 결과를 만들지 않아야 한다.
- 계정 변경·중지·철회 때 수집과 대기 자료의 소유권을 분리한다. 분석 로그에는 경로·이벤트 위치·
  집/회사·검색어를 보내지 않는다. 요약도 본인용 자료이며 자동으로 익명 자료라고 취급하지 않는다.

### 다음 질문과 아직 미정인 사항

먼저 사용자와 확인할 것은 **초기에는 관찰 중심으로 급가감속을 보여주고 과속 평가는 보류할지**,
**경로 비저장 상태에서도 별도 선택으로 요약 리포트를 허용할지**다.
이 두 경계 합의 뒤 기록 설정·세션 종료 범위·요약 동기화/보존/삭제·최소 품질 조건을 구체화한다.
점수 수식·등급·임계치·실기기 실증 계획·SDK 데이터 이용 조건과 네이티브 브리지 도입 여부는 남아 있다.
수집을 켜거나 현재 위치 동의/방문 저장 선택의 의미를 바꾸는 구현은 이 문서로 승인된 것이 아니다.
