# 노면 위험 정보 수명주기

노면 위험 제보가 지도와 길안내에서 어느 정도 신뢰도로 얼마나 오래 유지되는지, 사용자의
현장 확인과 해제 의견을 어떻게 반영하는지에 관한 결정 기록이다.

관련 구현:

- `supabase/migrations/20260824051417_revise_hazard_lifecycle.sql`
- `supabase/migrations/20260824053213_separate_hazard_report_from_confirmation.sql`
- `components/map/HazardMarker.tsx`
- `components/map/HazardSheet.tsx`
- `lib/navigation.ts`

## 먼저 확인할 활성 원칙

1. 위험 제보는 승인 대기 없이 즉시 공개하지만, 유형별 신선도 기간이 지나면 흐리게 표시하고
   길안내 경고에서는 제외한다. 유형별 최종 만료 시각이 지나면 조회 대상에서 제외하되 실제
   행은 삭제하지 않는다.
2. 마지막 확인 이후의 `없어졌어요`만 현재 해제 의견으로 센다. 한 표는 즉시 흐리게 만들고
   24시간 동안 새 확인이 없으면 제외한다. 두 명의 해제 표는 즉시 제외한다.
3. `아직 있어요`는 이전 해제 의견을 무효화하고 정보를 즉시 다시 활성화한다. 같은 사용자가
   나중에 다시 확인해도 확인 시각을 갱신할 수 있지만, 사용자별 마지막 유효 판단 후 6시간이
   지나야 다시 변경하거나 갱신할 수 있다.
4. 현재 선명하게 표시되는 정보만 길안내 전 위험 경고에 사용한다. 흐린 정보는 지도에서
   재확인만 유도한다.
5. 신뢰 상태는 단순 누적 표 수가 아니라 마지막 확인과 해제 의견의 시간 순서로 판단한다.
6. 최초 제보와 `아직 있어요` 확인 표는 구분한다. 제보는 수명 계산만 시작하고 확인 수에는
   포함하지 않는다. 제보자는 `없어졌어요`로 즉시 정정할 수 있지만, 자기 제보에
   `아직 있어요`를 추가하려면 6시간 뒤 다시 확인해야 한다.

## HAZ-000 — 긴 유형별 수명과 해제 2표 기준

- 날짜: 2026-08-14
- 상태: 대체됨(HAZ-001)
- 관련 구현: `hazard_fresh_days`, `live_road_hazards`, `vote_hazard`

### 배경

초기에는 사용자 참여가 적어도 제보가 너무 빨리 사라지지 않도록 결빙·기름 14일, 공사
30일, 나머지 120일을 신선도 기간으로 두었다. 같은 기간을 한 번 더 지난 뒤 제외하고,
`없어졌어요` 두 표가 모이면 즉시 제외했다.

### 결정

이 결정은 HAZ-001로 대체됐다. 당시 제보는 `last_confirmed_at`부터 신선도 기간 동안 선명하게,
그다음 같은 기간 동안 흐리게 표시한 뒤 제외했다.

### 검토한 대안과 시행착오

사용자가 적다는 이유로 긴 수명을 사용했지만 모래·결빙·기름 같은 일시적 위험까지 수개월
동안 유지될 수 있었다. 해제 표는 시점과 무관하게 누적되어 오래된 한 표와 최근 한 표가
합쳐질 수 있었고, 반대로 실제로 사라졌어도 두 사람이 참여하기 전에는 계속 남았다.

### 영향과 재검토 조건

과거 값으로 되돌리려면 단순히 사용자 수만 보지 않고 유형별 실제 지속 시간, 잘못된 경고가
신뢰에 주는 영향, 재확인 참여율을 함께 확인한다.

## HAZ-001 — 짧은 유형별 수명과 한 표 유예 해제

- 날짜: 2026-08-24
- 상태: 부분 대체됨(HAZ-002: 최초 제보와 확인 표 분리)
- 관련 구현: `20260824051417_revise_hazard_lifecycle.sql`, `HazardSheet.tsx`, `lib/navigation.ts`

### 배경

노면 위험은 많이 남아 있는 것보다 지금도 믿을 수 있다는 신뢰가 중요하다. 다만 사용자가
적은 단계에서 해제에 항상 두 명을 요구하면 사라진 위험이 오래 남고, 한 명의 의견만으로
즉시 완전히 숨기면 오판이나 악의적인 해제에 취약하다.

### 결정

유형별 신선도와 최종 만료 간격은 다음과 같다. 신선도 기간에는 선명하게 표시하고 길안내
경고에 사용한다. 이후 최종 만료 전까지는 흐리게 표시하며 재확인을 유도한다.

| 유형 | 신선도 | 최종 만료 |
|---|---:|---:|
| 결빙 | 6시간 | 24시간 |
| 기름·미끄럼 | 1일 | 3일 |
| 모래·자갈 | 3일 | 10일 |
| 낙석·흙 | 7일 | 21일 |
| 공사 구간 | 7일 | 30일 |
| 포트홀·파임 | 14일 | 60일 |
| 기타 위험 | 1일 | 7일 |

마지막 확인 이후 `없어졌어요` 한 표가 들어오면 즉시 흐리게 하고 길안내 경고에서 제외한다.
24시간 동안 더 새로운 `아직 있어요`가 없으면 지도 조회에서도 제외한다. 서로 다른 두 명의
해제 표가 모이면 유예 없이 제외한다. 이후 새 확인이 들어오면 해제 의견을 무효화하고 해당
유형의 신선도·만료 시간을 확인 시점부터 다시 계산한다. 제외된 데이터는 감사와 정책 재검토를
위해 보존한다.

최초 제보는 제보자의 첫 확인 표로 기록한다. 같은 사용자는 마지막 유효 판단으로부터 6시간이
지난 뒤에만 다시 확인하거나 상태를 바꿀 수 있다. 단, 제보자가 최초 확인을 `없어졌어요`로
바꾸는 첫 전환은 즉시 허용한다. 다른 사용자의 첫 판단과 다른 사용자들의 판단 주기는 서로
영향을 주지 않는다.

최초 제보를 확인 표로 기록하는 결정은 HAZ-002로 대체됐다. 이 문단은 짧게 운영에 반영됐던
과거 정책과 정정 이유를 보존하기 위해 남긴다.

### 검토한 대안과 시행착오

최근 7일 안에 두 표를 요구하는 안은 사용자 수가 적을 때 사실상 작동하지 않는다. 한 표로
즉시 제외하는 안은 빠르지만 잘못된 해제에 복구 기회를 주지 않는다. 한 표에 24시간 유예를
두면 즉시 경고 신뢰도는 낮추면서 새 확인으로 복구할 시간을 확보할 수 있다.

재확인 간격을 두지 않으면 한 사람이 `아직 있어요`를 반복해 수명을 무기한 연장하거나 상태를
빠르게 뒤집을 수 있다. 반대로 최초 해제까지 기다리게 하면 오제보를 바로 바로잡을 수 없으므로,
최초 제보자의 첫 해제만 예외로 두고 이후 판단에는 사용자별 6시간 간격을 적용한다.

신선도와 만료를 항상 2배 관계로 두는 방식도 버렸다. 결빙처럼 매우 짧은 위험과 포트홀처럼
오래 지속되는 위험은 흐린 상태로 재확인을 기다릴 기간도 서로 달라야 하기 때문이다.

### 영향과 재검토 조건

위험 유형별 제보 수, 확인·해제 참여율, 신선도 만료 전 재확인 비율, 잘못된 해제 복구 사례를
주기적으로 확인한다. 활성 제보가 충분히 쌓이면 위험 유형과 도로 상태에 따른 기간 세분화,
현장 근접 사용자 표의 가중치, 반복적인 오판·악용 방지를 검토한다. 기간 변경 시 이 문서,
간격 함수, 길안내의 `staleness` 필터를 같은 작업에서 동기화한다.

## HAZ-002 — 최초 제보와 명시적 확인 표 분리

- 날짜: 2026-08-24
- 상태: 활성
- 관련 구현: `20260824053213_separate_hazard_report_from_confirmation.sql`, `vote_hazard`

### 배경

HAZ-001을 처음 구현하면서 사용자별 재판단 간격을 만들기 위해 최초 제보를 제보자의 첫
`아직 있어요` 표로 기록했다. 그러나 최초 제보는 위험이 있다는 최초 주장이고, `아직 있어요`는
그 뒤 현장을 다시 확인했다는 별도의 판단이다. 둘을 같은 표로 세면 실제 재확인이 없는데도
확인 수가 1로 보이고 신뢰도를 과장한다.

### 결정

최초 제보는 `last_confirmed_at`의 초기값으로 유형별 신선도·만료 시간만 시작한다.
`confirm_count`와 `hazard_votes`에는 사용자가 명시적으로 누른 `아직 있어요`만 기록한다.

제보자는 오제보나 빠른 상황 변화를 바로 정정할 수 있도록 최초 `없어졌어요`를 즉시 누를 수
있다. 반면 자기 제보에 `아직 있어요`를 추가하려면 제보 후 6시간이 지나 실제 재확인으로 볼
수 있어야 한다. 다른 사용자의 첫 판단은 즉시 허용하며, 실제 표를 낸 뒤에는 모든 사용자가
자신의 마지막 유효 판단으로부터 6시간 뒤 다시 판단할 수 있다.

### 검토한 대안과 시행착오

최초 제보를 확인 1표로 간주하면 구현은 단순하지만 제보와 검증의 의미가 섞인다. 제보자의
모든 첫 투표를 6시간 막으면 오제보를 바로 취소하지 못한다. 따라서 제보자의 첫 해제는
허용하고, 자기 확인만 6시간 뒤로 제한한다.

운영에 자동 생성됐던 표는 제보자, `confirm` 유형, 제보 생성 시각이 모두 일치하는 행만
제거한다. 실제 사용자 표는 별도 RPC 트랜잭션에서 생성되므로 이 조건과 일치하지 않는다.

### 영향과 재검토 조건

확인 수는 독립 사용자 수가 아니라 명시적 현장 확인 표 수라는 의미를 유지한다. 향후 제보자
표를 아예 허용하지 않거나 현장 거리 검증을 도입할 경우 제보자 6시간 규칙과 함께 재검토한다.
