# 앱 성능 측정·최적화

화면 반응·자원 사용량을 어떻게 검증하고, 최적화 과정에서 무엇을 지켜야 하는지 기록한다.
실행 시나리오·비교 조건·결과 양식은 [성능 계획](../performance-optimization-plan.md)에서 관리한다.

## 활성 원칙

- 실측 전에 병목이나 최적화 효과를 확정하지 않는다. 코드상의 후보와 실제 관측을 구분한다.
- 개발 빌드는 원인 탐색에 사용하고, 최종 성능은 조건을 맞춘 실기기 release 계열에서 비교한다.
- 화면 첫 표시·핵심 조작 가능·선택 정보 준비, JS·네이티브 CPU·대기, heap·전체 메모리를 분리한다.
- 이미 적용한 windowing·구독 격리·이미지 제한은 효과를 검증한다. 기존 실패 접근을 되풀이하지 않는다.
- 속도를 위해 마커·검색·리뷰 등 결과를 누락하거나 위치·길안내 정확성, 레이아웃·gesture 계약을 깨지 않는다.
- 원본 위치·사용자 콘텐츠를 성능 로그에 넣지 않는다. 측정도 운영 중단·개인정보·릴리스 경계를 따른다.
- 병목 하나씩 수정해 전후 수치와 기능 회귀·트레이드오프를 남긴다. 측정 잡음 수준이면 효과 미확인이다.

## PERF-001 — 운영 중단 중에는 계획만, 재개 조건 충족 후 측정

- 날짜: 2026-10-04
- 상태: 활성(실행 계획·목표 수치는 초안, 앱 실측·수정 미착수)
- 관련 문서: [성능 계획](../performance-optimization-plan.md), [기존 성능 백로그](../../PLAN.md#성능구조-후순위-백로그)
- 관련 구현: `app/_layout.tsx`, `components/ActiveRootLayout.tsx`, `components/map/`,
  `components/ui/ImageViewer.tsx`, `hooks/usePlaces.ts`, `hooks/useUnifiedPlaceSearch.ts`,
  `lib/queryClient.ts`, `modules/kakao-navi/`

### 배경

화면 로드·메모리·CPU를 포함해 다방면으로 측정하고 개선할 계획이 필요하다. 다만 현재는
사업자·위치기반서비스 신고 보완·대기로 앱과 백엔드를 활성화할 수 없다. 코드 정리는
자동으로 성능 개선을 보장하지 않으며 기존 지도·사진 최적화와 네이티브 hang도 구분해야 한다.

### 결정

1. 지금은 코드·문서 검토와 외부 호출 없는 정적 검사만 한다. 앱 실행·계측 추가·DB 복구·API
   활성화·빌드·OTA는 하지 않는다. 측정을 이유로 중단 게이트를 우회하지 않는다.
2. [OPS-003](service-suspension.md)의 신고·보호조치 조건 충족 후 공개 상태 `preparing`을 유지하며
   승인된 내부 검증부터 시작한다. 별도 상시 내부 환경을 이번 계획에서 새로 만들지 않는다.
3. 네이티브 길안내 hang을 우선 조사하고, 시작·지도·상세·사진·긴 세션의 기준값을 수집한다.
   그 결과로 사용자 영향이 큰 병목을 선정한다. 모든 최적화를 공개 재개의 선행 조건으로 만들지 않는다.
4. 동일 기기·버전·캐시·데이터·네트워크·발열 조건에서 반복 비교한다. 실패·취소·표본 수를
   공개하고 평균만으로 완료를 선언하지 않는다. 목표값은 기준값 수집 후 조정한다.
5. 원인별 최소 커밋으로 측정 결과와 도메인 정책을 동기화한다. 네이티브·DB·의존성·계측 등
   계획 실행 작업의 푸시·배포는 승인 후 진행하고 지원 runtime의 기능 회귀를 확인한다.

### 검토한 대안과 시행착오

- **지금 앱·DB를 열어 측정:** 신고·운영 중단 경계를 넘으므로 채택하지 않는다.
- **무조건 memo·캐시 축소·SDK 업그레이드:** 실제 병목 근거가 없고 요청 증가·호환성 회귀가 가능하다.
- **평균 FPS·JS heap만 확인:** 네이티브 I/O 대기, 이미지·지도 메모리, 긴 프레임을 놓친다.
- **기존 최적화 재구현:** 지도 windowing·구독 격리·원본 ±1 렌더는 이미 적용됐다.
  먼저 효과·경계 조건을 검증하고 과거 마커 캡처·텍스처 폭주·검색 카메라 회귀를 피한다.

### 영향과 재검토 조건

- 새 성능 수치는 실제 측정 이후에만 보고서에 추가한다. 가설·목표를 측정 결과처럼 표시하지 않는다.
- 프로파일 원본은 비공개로 관리하고 저장소에는 위치·사용자 정보가 제거된 요약만 남긴다.
- SDK·runtime 전환, 대규모 데이터 증가, 성능 회귀, 운영·개인정보 경계 변화가 있으면
  이 기록과 계획·관련 도메인·백로그를 함께 갱신한다. 이전 결과는 후속 결정과 연결해 보존한다.
