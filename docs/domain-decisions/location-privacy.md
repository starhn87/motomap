# 위치정보 이용·자료 관리

## LOC-001 — OS 권한과 서비스 동의를 분리하고 권리 행사를 기능으로 제공

- 날짜: 2026-10-11
- 상태: DB 적용·기존 자료 보존 검증 완료 / 최초 동의·관리 화면 구성은 LOC-002로 대체, 실기기 검증 대기
- 관련: OPS-010, `constants/legal.ts`, `lib/locationPrivacy.ts`,
  `stores/useLocationPrivacyStore.ts`, `components/LocationPrivacyPanel.tsx`,
  `supabase/migrations/20261011142734_add_location_privacy_controls.sql`

### 결정

전문 법률 검토를 추가 출시 조건으로 요구하지 않는다. 아래 공식 의무에 대응하는
기술적 수단을 구현하고 실제 검증·운영 증빙을 남긴다. 이 작업을 법적 적합성 인증으로 표시하지 않는다.

1. 회원·비회원 모두 현재 위치 이용 전 별도 미선택 체크박스(만 14세 이상·위치 약관)를
   확인한다. OS 권한만으로 동의했다고 처리하지 않는다. 만 14세 미만의 법정대리인 동의
   절차는 현재 지원하지 않으며 개인위치 기능을 열지 않는다.
2. 카카오·기상청·한국환경공단·한국석유공사·Anthropic의 목적/항목을 별도로 안내·선택한다.
   선택하지 않은 공급자의 좌표 호출은 하지 않는다. 네이버 지도 현재 위치 표시는 기본
   위치 이용 안내에 포함한다. 좌표 기반 조회는 수동 지점인지 GPS인지 추정하지 않고
   보수적으로 동의 후 허용한다. 비동의 텍스트 검색은 위치 편향을 보내지 않는다.
3. 새 방문·완주 저장은 로그인 이용자의 별도 선택사항이다. 해제는 새 저장 중지이며
   기존 보유 자료 삭제는 별도 명확한 철회/삭제 확인 후 수행한다. 기존 리뷰·즐겨찾기는 유지한다.
4. 설정 → 위치정보 동의·기록 관리에서 일시 중지·재시작, 전부 철회, 방문 기록 보유 철회,
   공급자 범위 변경, 본인 확인자료/방문/완주 열람, 개별·전체 기록 삭제를 제공한다.
   집·회사 통계 제외 기록도 열람 대상이다. 새로운 동의 없이 기존 자료 열람·삭제 가능하다.
   정정·추가 열람은 자료 ID를 포함한 문의 버튼으로 접수하고 운영자가 본인 확인 후 처리한다.
5. 일시 중지는 현재 위치 캐시·JS 센서·진행/대기 길안내를 닫는다. 서버 실패 시 자동으로
   다시 켜지 않는다. 철회는 해당 확인자료/방문/완주를 파기하며 공급자 해제는 해당 공급자
   확인자료를 파기한다. 토큰 전환 중 다른 계정의 자료를 처리하지 않도록 서버에서
   expectedActor와 auth.uid 일치를 검사한다. 계정 ID 인자로 타인 권한을 부여하지 않는다.
   중지·철회 서버 실패 시 actor별 기기 보안 저장소의 대기 의도를 우선해 앱 재시작 뒤에도
   자동 재개하지 않는다. 전부 철회가 미완료라면 재동의 전에 해당 파기를 먼저 완료한다.
   미완료 방문 기록 철회도 약한 중지·개별 삭제·재시작 요청으로 덮지 않고 파기를 먼저 완료한다.
   저장소 오류가 있어도 네이티브 중지는 먼저 시도하고 저장·조회·서버 처리 실패를 성공으로 표시하지 않는다.
6. 비회원 소유권은 보안 저장소의 256bit 비밀값과 SHA256 해시로 확인하며 로그인 계정과
   자동 병합하지 않는다. 비밀값을 분석·오류 로그에 넣지 않는다. 비밀값 분실 시 다른 기기의
   익명 자료를 추측해서 조회하거나 계정 자료에 병합하지 않고 운영 문의로 처리한다.

### 확인자료와 보호

- 별도 private schema/RLS/직접 앱 테이블 권한 없음. 공개 invoker RPC → private definer에서
  본인 계정 또는 기기 해시를 판별한다. 최소 역할·빈 search_path·짧은 SQL 제한을 적용한다.
- 기능 요청 단위로 서버 시각·목적·공급자·요청 결과만 기록한다. 좌표·주소·검색어는
  확인자료에 복제하지 않는다. 방문 자료의 좌표는 별도 본인 열람 대상이며 패널 전체를
  PostHogMaskView로 가린다. 명시적 내보내기만 공유 시트를 연다.
  요청 안내는 서버 확인자료의 시각을 날짜·시간 함께 표시한다. 설정 거절 시 내 위치 버튼과
  길안내는 설정 진입을 안내하며 영구 로딩하지 않는다. 권한 없는 경로·출발지 캐시도 표시하지 않는다.
- 위치정보법 제16조의 확인자료 기록·보존과 제24조의 철회·파기 원칙에 맞춰 **6개월**을
  보유 정책으로 정한다. 이 기간을 모든 자료의 일률적 법정 최소 보유기간으로 설명하지 않는다.
  매일 17:00 UTC(한국 02:00) 만료 확인자료와 오래된 quota를 정리한다. 철회 범위 자료는 즉시 삭제한다.
- `completed`는 요청 함수의 응답을 받은 상태이며 HTTP/Edge의 최종 기능 성공을 보장하지 않는다.
  요청 실패·중지·결과 미확인을 분리 표시한다. 외부 기능 요청 직전 공급자·목적·서버 기록 시각 안내를
  표시하며 안내 중에는 네이티브 notice를 사용한다. 이는 SDK 내부 GPS 프레임별 전송을 추적하는
  로그가 아니다. SDK 실제 전송·중지 범위는 새 바이너리 검증에서 확인한다.
- 기기당 시간당 1000건 외 프로젝트 일간 subject 생성 1000건/이벤트 20000건 상한도 둔다.
  secret 회전으로 저장량 상한을 우회할 수 없다. 상한 초과는 기능 호출 전 실패로 처리한다.
  상한은 IP 기반 공격 방어의 완전한 대체가 아니며 경보·규모 변경은 운영 점검 대상이다.
- native 초기화·경로/안내 시작·중지는 main 큐, SDK 후속 콜백도 같은 큐에서 허용 상태와
  generation을 확인한 후 다음 요청을 수행한다. CoreLocation 시작 검사와 실제 시작/정지는
  공통 잠금으로 묶어 중지 이후 늦은 시작을 막는다. 활성 guidance.stop은 공식 헤더의
  GPS 모니터링 해제 API를 사용하고, SDK 초기화의 추가 manager 해제는 기존 스위즐을 확장한다.
  이 manager 식별/스위즐은 공개 SDK의 전역 stop API가 아니므로 실제 background GPS 해제와
  앱 자체 Expo 센서가 잘못 막히지 않는지는 승인 후 실기기 검증의 필수 항목이다.
- 방문 INSERT 트리거는 subject 행을 FOR SHARE로 잠가 철회의 FOR UPDATE와 직렬화한다.
  기존 데이터의 등록/일반 전환, 집·회사 통계 제외, 바이크 FK 정리를 막지 않도록 UPDATE
  트리거는 넣지 않는다. 현재 UPDATE RLS 부재/권한 제한을 원격 적용 전 재확인한다.

### 이전 결정·호환성

OS 위치 권한만으로 서버 동의 철회를 대체한다는 과거 약관 문구는 대체한다.
일시 중지 시 기록을 삭제하거나 새 동의 선택만으로 과거 기록을 일괄 삭제하는 대안은 제외했다.
이전 회원 동의 38건·방문 39건을 마이그레이션에서 삭제/소급 동의 처리하지 않는다.
첫 재동의·새 저장 선택 전에는 신규 방문 INSERT를 거부한다. 기존 기록은 본인에게 계속 제공한다.

앱/runtime 1.2.8 미출시 후보에서 native bridge 2(`location_privacy_stop`)를 추가한다.
기존 내부 36/production 37 후보에는 이 기능이 없다. 이 변경은 OTA 단독으로 배포하지 않는다.
원격 마이그레이션·새 빌드·실기기 중지/철회·서버 소유권/cron 검증 후에만 제출한다.
기존 1.2.7 동의/가입 RPC는 보존하되 새 방문 쓰기는 동의 트리거 적용 후 차단될 수 있다.
구버전은 계속 중단/업데이트 대상이다. public active 전환·전체 푸시는 별도 승인 대상이다.

### 2026-10-11 승인 후 적용·빌드 후속

운영자가 DB 적용·새 빌드·실기기 검증을 승인했다. 실제 원격 적용 버전은
`20261011142734_add_location_privacy_controls`이며 원문 지문이 동일한 저장소 파일도 이 이름으로 맞춘다.
리뷰 16건·즐겨찾기 20건·방문 41건과 기존 동의·이력 각각 38건은 전후 전체 행 체크섬이 같았다.
실제 DB의 임시 fixture 계약 19개 및 독립 두 세션의 철회 잠금/방문 INSERT 경합 검사를 통과했고,
fixture 계정·자료는 전부 제거했다. 만료 함수 실행은 롤백 fixture에서 확인했고 cron의 실제 예약
실행 결과와 혼동하지 않는다. 기존 자동 작업 3개는 계속 정지 상태다.

실기기 준비 중 재개 약관 ‘보기’가 아직 미배포 웹 본문을 열 수 있음을 확인했다.
재개 동의 화면은 앱의 `LEGAL_DOCS` 최신 본문을 내장 문서 모달로 보여준다. 위치 동의 패널도 같은
정본을 사용하며, 문서를 읽기 위해 서버 공개·라우팅 게이트를 우회하지 않는다. 웹 고지의 실제
동기화는 여전히 공개 전 승인·배포 대상이다. 앱에서 본문을 보여줬다고 웹까지 갱신됐다고 표시하지 않는다.

## LOC-002 — 첫 동의는 한 화면, 상세 선택·자료 관리는 설정으로

- 날짜: 2026-10-12
- 상태: 사용자 승인 후 구현·검증 중
- 대체: LOC-001의 최초 동의·관리 화면 배치만 대체한다. 서버 보호·철회·소유권·보존 정책은 유지한다.

사용자는 지도 앱에 비해 첫 화면이 과도하게 복잡하다고 지적했다. 일반 약관 화면과 위치 관리
패널을 연속 표시하는 방식은 폐기한다. 로그인 이용자는 미선택 3개(14세 이상·이용약관,
개인정보 처리방침, 위치 이용·전달), 일반 약관 확인이 끝난 계정과 비회원은 위치 동의 1개를
한 화면에서 확인한다. 연령 확인은 해당 체크 문구에 명시한다. 자동 동의하거나 운영자가
테스트 중 이용자를 대신해 체크하지 않는다. 공급자 기본 범위는 동의 전에 안내하며 위치
‘보기’에서 수신자·목적·항목을 확인하고 개별 선택을 해제할 수 있다. 이미 선택한 범위는 보존한다.
상세 화면을 보지 않았다는 이유로 별도 서버 동의를 만들어내는 대신 명시적 위치 동의 체크가
화면에 안내된 선택 범위를 포함한다. 최초 방문 저장은 OFF다.

설정 첫 화면은 현재 위치 사용·방문 기록 저장 스위치와 동의 범위 변경·내 기록·철회 진입만
표시한다. 상세 열람·내보내기·정정·삭제는 ‘내 기록’ 안에 둔다. 삭제와 철회는 명확한 확인을 유지한다.
방문 저장 OFF는 새 저장만 막고 기존 자료, 위치 상태, 공급자 범위, 동의 시각을 유지한다.
`set_location_history_enabled`는 본인/활성 동의/행 잠금을 검증하고 `history_allowed`만 바꾼다.
성공한 스위치 조작은 GPS·길안내를 끊지 않는다. 실패하면 안전하게 중지하고 대기 의도를 저장한다.
OFF에 재동의 또는 `withdraw_history`를 사용해 과거 자료까지 지우는 방식은 금지한다.

동일 계정의 토큰 갱신·약관 확인 완료는 위치 상태를 다시 초기화하지 않는다. 실제 계정 전환만
상태를 다시 조회한다. 일반 약관 수락은 화면 시작 시 계정 JWT를 개별 요청 헤더에 고정해
SDK가 뒤늦게 다른 계정의 토큰을 읽더라도 그 계정에 동의가 저장되지 않도록 한다.
자료 조회도 계정·revision을 검증하고 UI 마스킹을 유지한다.

사용자는 DB 보완·새 내부 빌드·실기기 검증을 승인했다. Git 푸시·웹/OTA 배포·TestFlight 업로드·
심사 제출·판매 재개·전체 알림은 별도 승인 전 실행하지 않는다. 법률 고지 10/11 시행 설정을
이번 화면 변경만으로 소급 변경하지 않는다. 실제 고지 공개 시점 변경은 OPS-010에 따라 확인한다.

실기기 후속 피드백: 연령 문구 뒤에 한두 글자만 다음 줄로 남는 것을 피하려고 동의 행을
‘만 14세 이상 · 위치 이용·전달 동의’ 등 짧은 표현으로 줄인다. 연령·이용·전달의 의미와 상세
본문·공급자 범위·명시적 체크는 유지한다. 작은 화면/큰글자에서는 자연스러운 줄바꿈을 허용하며
