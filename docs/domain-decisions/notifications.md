# 알림 탭과 화면 진입

## NOTIFY-001 — 승인 알림의 상세 요청을 시작·OTA 경계에서도 보존한다

- 날짜: 2026-10-14
- 상태: 소스 보완·1.2.8 iOS OTA 발행 완료(실기기 적용·상세 진입 확인 대기)
- 관련 구현: `lib/push.ts`, `lib/notificationNavigation.ts`,
  `lib/serviceResumeNotification.ts`, `lib/setupServiceResumeNotification.ts`, `app/_layout.tsx`

### 배경과 확인한 사실

운영자가 장소 제보 승인 푸시는 받았지만 탭해도 추가된 장소 상세로 이동하지 않는다고 보고했다.
당시 앱이 완전히 종료돼 있었는지 기억하지 못해 콜드·웜 두 경로를 점검한다.

- 운영 DB 읽기 전용 확인: 최근 승인 알림에 문자열 `placeId`가 있고 해당 장소가 존재하며
  상세 조회용 `all_places` RPC에도 포함된다. 승인 트리거는 `type: place_approved`와 `placeId`를 보낸다.
- 일반 탭 처리는 `content.data`만 읽었고 재개 알림만 iOS 원본 `trigger.payload.body/data`를
  확인했다. 설치된 Expo Notifications 57은 보통 `userInfo.body`에서 data를 만들지만 원문만
  있는 응답도 방어해야 한다. 실제 문제 기기의 원본 응답을 확보한 것은 아니다.
- 루트가 일반 탭을 `none`으로 판단해 시작 중 OTA 다운로드·reload를 허용했다.
  native emitter가 교체되면 활성 앱이 뒤늦게 읽는 마지막 응답이 사라질 수 있다(OPS-012).
- Expo Router의 push는 큐를 사용하므로 단순히 Stack 준비가 늦다는 이유로 확정하지 않는다.

### 결정

1. 명시적인 기본 탭만 처리한다. 가공된 data를 우선하고 iOS push 원문의 body/data를 같은
   파서로 확인한다. 모르는 타입·잘못된 대상 ID에서 새 상세 경로를 만들지 않는다.
2. 승인 장소는 알림 목록과 동일한 `focusPlaceOnMap`으로 지도에 포커스하고 장소 상세를 연다.
   기존 지도 인스턴스를 유지하고 옛 일반 장소의 `kakao*`/`generalPlaceId`를 비워 새 nonce로
   이전 선택이 다시 소비되지 않게 한다. 반려·답변처럼 상세가 없는 알림은 기존
   목록 진입을 유지한다. 재개 알림의 스토어 연결은 루트에만 맡긴다.
3. 유효한 일반 알림은 시작 판정 `navigation`으로 넘겨 해당 실행의 OTA 강제 reload를
   생략한다. 다운로드 도중 들어온 탭도 reload 직전에 다시 확인한다. 알림 없는 시작은 기존 OTA
   확인·다운로드·재시작을 그대로 수행한다. 게이트·동의 우회나 SDK 선행 초기화는 하지 않는다.
4. 콜드 조회보다 새 웜 탭이 우선하고 같은 응답이 1초 안에 연속 전달될 때만 합친다.
   같은 알림을 나중에 다시 탭하면 새 상세 요청으로 처리한다. 언마운트 후에는
   라우팅하지 않는다. 성공한 마지막 응답은 최신 응답이 바뀌지 않았을 때만 비워 재진입을 막는다.
   라우터에 요청을 전달한 것이 실제 장소 시트 표시를 증명하지는 않는다.
5. 서버·DB·알림 기록·푸시 토큰·네이티브 계약은 변경하지 않는다. 테스트 푸시를 무단 발송하지 않는다.

### 검증과 재검토

네이티브 API·라우터 대역으로 실제 앱 JS를 실행해 콜드/웜, 원문 폴백, 초기/다운로드 중
OTA 경계, 중복/늦은 응답, 정리·실패 재시도와 기존 알림 이동을 검사한다.
이는 실기기 푸시→장소 시트 완료 검증을 대체하지 않는다. 재발하면 실제 응답 형태와
지도 요청 소비·조회 취소를 추가 확인하되 토큰·본문·좌표·사용자 ID를 로그에 남기지 않는다.

2026-10-14: 타입 검사, 전체 앱 테스트 231/231, 웹 테스트 5/5, OTA 호환성 검사와
변경 리뷰를 통과했다. 앱/runtime 1.2.8·native 2·API 1은 그대로다.
이 검증 시점에는 실제 기기 승인 알림 응답 확보·테스트 푸시·Git 푸시·OTA 발행은 미실행이었다.

푸시를 발송하지 않았으며 실기기 검증을 위해 임의 알림을 추가하지 않는다.
