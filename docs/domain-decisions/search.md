# 통합 검색·검색 결과 지도

텍스트 검색에서 등록 장소·일반 장소·코스를 찾고, 결과 지도에서 위치를 비교하는 경험에
관한 결정 기록이다.

관련 구현:

- `app/search.tsx`
- `app/search-results.tsx`
- `components/search/PointSearchModal.tsx`
- `hooks/useSearchAnchor.ts`
- `lib/api/search.ts`

## 먼저 확인할 활성 원칙

1. 검색 기준점은 마지막으로 본 지도 중심을 우선하고, 없으면 사용자 위치를 사용한다.
2. 검색 결과 지도는 기준점 중심 고정 20km 안의 등록 장소·일반 장소·코스로 제한한다.
   주변 결과가 없어도 결과 지도에 전국 결과를 붙이지 않는다.
3. 사용자에게 보이는 결과 순서는 등록 장소, 카카오 일반 장소, 코스 순이다. 코스는 항상
   장소 결과 뒤에 둔다.
4. 이름·태그·주소 등의 매칭 점수는 정렬을 위한 내부 정보다. “이름이 정확히 일치” 같은
   구현 설명은 결과 행에 노출하지 않는다.
5. 결과 지도에 위치가 하나뿐이면 바텀시트를 제외한 지도 영역의 중앙에 마커를 둔다.

6. 검색 입력 화면과 길찾기 지점 검색은 먼 고유 장소·지역명도 찾을 수 있도록 주변 우선
   검색을 유지한다. “현재 지도 결과를 한눈에 보는 화면”과 “목적지를 직접 찾는 입력”의
   범위는 의도적으로 다르다.

## SEARCH-001 — 결과 지도는 주변 목록만 사용

- 날짜: 2026-08-21
- 상태: 활성
- 관련 구현: `app/search.tsx`, `app/search-results.tsx`, `lib/api/search.ts`
- 대체한 동작: 커밋 `36d24cd`의 주변·전국 결과 무조건 결합

### 배경

결과 지도에서 주변 20km 조회와 전국 조회를 병렬 실행해 합치면서 “카페”처럼 범위가 넓은
검색어에 전국 등록 장소가 모두 붙었다. 카카오 일반 장소는 이미 20km로 제한되어 데이터
출처별 범위도 서로 달랐고, 가까운 장소를 찾으려는 검색의 실용성이 사라졌다.

### 결정

검색 결과 지도에서는 기준점 20km 안의 등록 장소·카카오 일반 장소·코스만 사용하며,
주변 결과가 없어도 전국 결과로 폴백하지 않는다. 결과는 등록 장소, 카카오 일반 장소,
코스 순으로 보여준다. DB의 이름·태그·주소 점수는 정렬에만 사용하고 사용자 문구로
번역해 반복 노출하지 않는다.

검색 입력 화면과 길찾기 지점 검색은 지역명이 포함된 검색이나 먼 고유 목적지를 직접 찾는
경로이므로 주변 우선·전국 폴백과 카카오 위치 편향을 유지한다. 여기서 결과 하나를 직접
선택하면 해당 장소로 이동할 수 있다.

### 검토한 대안과 시행착오

주변 결과 뒤에 전국 결과를 모두 붙이면 별도의 범위 토글 없이도 모든 결과를 볼 수 있지만,
일반 카테고리 검색에서는 관련성보다 데이터 양이 앞서게 된다. 결과 지도는 주변 목록만으로
완결하고, 전국 목적지 탐색은 검색 입력 화면의 직접 선택 경로에 남긴다.

### 영향과 재검토 조건

현재 “지도 반경”은 실제 화면 경계가 아니라 지도 중심 기준 고정 20km다. 줌별 실제
뷰포트를 검색 범위로 쓰려면 지도 경계 저장, 캐시 키, PostGIS 범위 조회를 함께 설계한 뒤
재검토한다. 검색 입력은 먼 목적지 직접 선택, 결과 지도는 현재 지역 비교라는 의도된 범위
차이가 흐려지지 않게 두 화면을 함께 비교한다.

## SEARCH-002 — 단일 결과는 가시 지도 영역의 중앙에 배치

- 날짜: 2026-08-21
- 상태: 활성
- 관련 구현: `app/search-results.tsx`

### 배경

위치 결과가 하나여도 가상의 좌표 범위를 만들어 복수 결과용 카메라 맞춤을 적용했다. 남북
여백이 비대칭이라 마커가 위쪽으로 치우쳤고, 실제 결과 바텀시트 높이는 계산에 쓰이지 않았다.

### 결정

지도 초기화와 검색 로딩이 끝난 뒤 위치 결과가 하나면 `animateCameraTo`의 `pivot`을 사용한다.
세로 기준점은 `(화면 높이 - 결과 시트 높이) / 2 / 화면 높이`로 계산해 바텀시트를 제외한
영역의 중앙에 둔다. 복수 위치 결과만 기존 좌표 범위 맞춤을 사용한다. 상세가 열려 있는
동안에는 결과 카메라 보정이 상세 카메라 이동을 덮지 않는다.

### 검토한 대안과 시행착오

최소 위·경도 범위를 강제로 만들어 복수 결과 API를 재사용하면 기기별 시트 높이와 무관한
임의 위치가 된다. 위도 오프셋 상수를 다시 맞추는 대신 SDK가 제공하는 화면 비율 기준점을
사용한다.

### 영향과 재검토 조건

결과 시트의 기본 스냅 포인트를 바꾸면 단일 결과 pivot도 같은 높이를 계속 참조해야 한다.
등록 장소 한 개, 일반 장소 한 개, 필터 후 한 개, 상세를 닫고 목록으로 돌아온 경우를 함께
검증한다.
