# 라이딩 지도 TestFlight 실기기 체크리스트

라이딩 경로 기록은 KNSDK 길안내 화면과 Expo 포그라운드 위치 구독이 함께 유지되는지 실제
기기에서 확인해야 한다. 운전 중 앱을 조작하지 말고, 앱 전환·강제 종료 같은 조작은 정차한 뒤
수행하거나 동승자가 진행한다.

## 사전 조건

- `ride_sessions`와 `ride_recording_consents` 마이그레이션이 먼저 적용돼 있다.
- 같은 `1.2.7` runtime의 최신 production OTA를 받은 TestFlight 앱이다.
- 로그인과 정확한 위치 권한이 켜져 있다.
- 설정에서 `라이딩 경로 기록`을 눌러 별도 동의한 뒤 스위치가 켜져 있다.
- 테스트 전후 시각과 목적지를 메모한다. 실제 좌표나 경로는 이슈·Discord·Sentry에 첨부하지 않는다.

## 필수 1 — 약 10분 정상 주행

1. 경로 미리보기에서 실제 길안내를 시작한다.
2. 화면을 켠 상태로 약 10분 주행하고 목적지 근처에서 안내를 종료한다.
3. `내 정보 > 주행 기록 > 라이딩 지도`를 연다.
4. 아래를 확인한다.

   - 새 세션이 한 번만 보인다.
   - 출발·주행·도착 경로가 실제 도로 흐름과 대체로 맞는다.
   - 재생 시 선이 진행 방향으로 늘어나고 마커가 경로를 따른다.
   - 거리와 이동 시간이 실제 주행과 현저히 다르지 않다.
   - 지도 경로나 최근 카드에서 같은 개별 라이딩 상세를 열 수 있다.

## 필수 2 — 앱 전환과 누락 구간

1. 새 길안내 중 안전하게 정차한 뒤 다른 앱으로 전환하고 30초 이상 기다린다.
2. 모토맵으로 돌아와 주행을 재개하고 안내를 종료한다.
3. 해당 상세가 `일부 기록`으로 표시되는지 확인한다.
4. 앱이 보이지 않았던 전후 좌표가 직선으로 이어지지 않고 서로 다른 선분으로 보이는지 확인한다.

## 필수 3 — 취소와 강제 종료 복구

1. 짧은 길안내를 시작하고 목적지에서 먼 곳에서 정상 종료한다. 상세 상태가 `종료`인지 확인한다.
2. 다시 길안내를 시작해 두 점 이상 이동한 뒤 정차 상태에서 앱을 강제 종료한다.
3. 앱을 다시 열고 네트워크가 연결된 상태로 잠시 기다린다.
4. 복구된 세션이 `중단 · 일부 기록`으로 한 번만 나타나는지 확인한다.

## 선택 — 오프라인 동기화

1. 길안내를 종료하기 직전에 네트워크를 끈다.
2. 종료 후 라이딩 파일이 앱 동작을 막거나 오류 모달을 만들지 않는지 확인한다.
3. 네트워크를 켜고 앱을 백그라운드로 보냈다가 다시 연다.
4. 세션이 한 번만 동기화되고 같은 기록이 중복되지 않는지 확인한다.

## 기록·삭제 정책

- 설정 스위치를 끈 뒤 새 길안내를 해도 새 경로가 생기지 않아야 한다. 기존 경로는 유지된다.
- 개별 상세에서 삭제하면 그 경로만 사라지고 장소 방문 횟수는 유지돼야 한다.
- `경로 전체 삭제 및 동의 철회`는 마지막에만 시험한다. 서버 경로와 기기 동기화 대기 파일이
  모두 사라지고, 다시 기록하려면 별도 동의가 필요해야 한다.
- 동의가 만료되면 경로가 즉시 조회에서 사라지고 5분 안에 서버 행도 삭제되는지는 운영 SQL로
  별도 확인한다. 실제 테스트를 위해 기기 시간을 변경하지 않는다.

## 합격 기준

필수 1~3에서 길안내 자체의 종료·리뷰 제안·지도 복귀가 경로 기록 실패 때문에 막히지 않고,
허위 직선·중복 세션·다른 계정의 경로 노출이 없어야 한다. 실패 시 실제 좌표 대신 앱 버전,
OTA ID, 시작·종료 시각, 점/선분 개수, 종료 상태만 기록해 재현한다.
