# 위치정보 처리·권리 요청 지침

기준: LOC-001 / 2026-10-11. 소스 준비 단계이며 원격 적용·실기기 검증 완료를 뜻하지 않는다.

## 책임·접근

위치정보 보호책임자·현재 접근권한자는 대표 이승우다. 문의는 공통 약관의 이메일·전화로 접수한다.
외부 인력에게 service_role/DB 비밀번호·비회원 비밀값을 전달하지 않는다. 관리 계정 MFA,
접근 인원·권한과 접근 이력은 재개 전 실제 콘솔에서 확인·증빙한다. 인원 변경 시 즉시 회수한다.
개인위치정보를 분석용 데이터셋·Git·스크린샷 보고서·임시 평문 파일에 복사하지 않는다.

## 처리·보존·삭제

- 사용 동의는 OS 권한과 별도로 본인 계정 또는 기기 해시를 기준으로 저장한다.
- 목적·공급자 선택 밖의 위치 호출은 중지한다. 연속 GPS 경로를 모토맵 서버에 저장하지 않는다.
- 방문 기록은 별도 저장 선택 후에만 생성하며 집·회사 통계 제외 기록도 개인 자료로 취급한다.
- 확인자료는 기능 요청 단위 최소 필드로 6개월 보관한다. 일반적인 원시 좌표 보유 근거로 쓰지 않는다.
- 전부 철회/부분 철회는 관련 자료를 지체 없이 삭제한다. 일시 중지는 보관 자료를 임의 삭제하지 않는다.
- cron 활성·최근 성공·만료 잔존 0 여부를 배포 직후와 월 1회 확인한다. 실패 시 담당자가 복구하고
  완료 시각·영향·삭제 건수만 기록한다. 기존 운영 스케줄러 3개 활성화는 별도 승인 범위다.
- 백업/PITR은 서비스 DB 삭제와 별개다. 공급자 보존기간·사본 접근을 확인하고, 복원할 때는
  철회·삭제 요청을 재적용한 뒤 서비스에 노출한다. 백업 즉시 영구 파기까지 완료했다고 표시하지 않는다.

## 열람·고지·정정·삭제 요청

### 서비스 요청 안내와 제3자 제공 통지

LOC-003에 따라 기존 검색·주소·날씨·유가·경로·길안내·AI 서비스 요청은 공급자 범위 동의와
확인자료 기록을 유지하되 반복 팝업은 표시하지 않는다. 요청 기록 열람으로 법정 통지를 대체한다는
정책은 아니다. 현재 목적·수신자 분류 밖의 외부 요청은 자동으로 팝업 생략하지 않는다.
이용자가 지정한 제3자에게 개인위치정보를 제공하는 서비스를 도입하면 수신자·목적을 고지하고
별도 동의를 받은 뒤 매회 실제 제공받는 자·제공일시·제공목적을 즉시 통보하도록 구현·검증한다.
현재 API 요청 시각 안내만으로 해당 제공 통지를 구현했다고 하지 않는다. 공급자 처리 목적·계약이나
공유 기능이 바뀌면 고지·분류·동의·통지·기록을 함께 재검토한다.

### 권리 요청 처리

1. 앱 본인 자료 열람은 인증된 계정/비회원 기기 비밀값으로만 허용한다. 문의에 비밀번호·OTP를 요구하지 않는다.
2. 문의 수신 시 요청 종류·수신일·자료 ID·처리 담당을 접근 제한된 운영 기록에 남긴다. 원시 주소·좌표를
   기록에 복제하지 않는다. 공개 Git 이슈로 개인 요청을 처리하지 않는다.
3. 로그인 계정의 기존 인증된 이메일 등 최소 수단으로 본인을 확인한다. 비회원 기기 비밀값 분실 시
   추측한 장소·시간만으로 다른 사람의 기록을 열람/삭제하지 않는다. 확인 가능한 범위와 대안을 안내한다.
4. 정정 대상에 오류가 있는지 확인하고, 확인 전 해당 자료의 추가 사용/제공을 중지한다. 앱 일시 중지와
   별개로 문의 접수 자료의 사용 보류를 운영자가 처리한다. 수정·파기 전후 영향과 결과를 당사자에게 알린다.
5. 동의 범위 밖의 요청을 거절하거나 새 위치 동의를 열람 전제조건으로 요구하지 않는다. 정당한 사유 없이
   지연하지 않으며 추가 확인 필요 시 구체적인 이유·진행 상태를 알린다.
6. 처리 기록에 담당자·요청/처리 시각·조치 종류·결과를 남긴다. 사용자 확인자료와 관리 취급대장을
   혼동하지 않는다. 관리 취급대장 최소 보관 기준은 공식 보호조치 기준에 대조하며 접근 제한하여 보관한다.

## 공개 전 승인 후 실행

1. 기존 리뷰·즐겨찾기·방문·완주 전체 행 비식별 체크섬과 RLS/권한을 읽기 전용으로 재확인한다.
2. 승인된 위치 privacy 마이그레이션을 적용한다. 기존 기록은 삭제하지 않는다. 익명/회원 본인 권한,
   계정 전환 CAS, 동의 없는 기존 기록 열람, 부분/전부 철회는 테스트 계정과 rollback로 검증한다.
3. 두 세션 동시 INSERT/철회 잠금 검사와 실제 pgcrypto/cron/Advisor·생성 타입을 검증한다.
4. native bridge 2 포함 새 production/내부 빌드에서 위치 권한 거절, 비동의/중지/철회, 진행·대기 길안내 중지,
   백그라운드 GPS 해제, 재시작, 계정 전환, 화면 마스킹을 실기기로 확인한다. 타입 체크가 native 실행 검증은 아니다.
5. 앱/웹 같은 약관 원본·고지일/시행일·동의 버전·ASC 개인정보/리뷰어 노트를 실제 공개 상태와 동기화한다.
6. 검증되지 않은 build 36/37은 심사 제출하지 않는다. Git 푸시·웹/OTA 배포·빌드·심사 제출은 별도 허락받는다.

## 로컬 SQL 검사 재현

프로젝트 의존성을 바꾸지 않고 `mktemp -d`로 만든 전용 폴더에
`npm install --prefix <임시폴더> --no-audit --no-fund @electric-sql/pglite@0.5.8`을 설치한다.
`PRIVACY_SQL_ENGINE=<임시폴더>/node_modules/@electric-sql/pglite/dist/index.js node tests/locationPrivacy.sql.test.mjs`
로 fixture를 실행한다. .env·운영 서버를 읽지 않는다. 실제 확장 바이너리·PostgREST·다중 세션 잠금·cron 실행은
별도 승인 후 검증하며 fixture 결과로 대체하지 않는다.
