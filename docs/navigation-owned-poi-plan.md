# 길안내 자체 POI 구성 계획

작성: 2026-10-28. 상태: **A~D 및 운영 데이터 표시 사용자 확인 완료. NAV-054 대비·일반 장소 누락 후속 검증 중(native36)**. 관련 결정: NAV-048, NAV-051, NAV-052, NAV-053, NAV-054.

목표는 길안내 화면에서 SDK 기본 상호·건물명 POI를 숨기고, 라이더에게 필요한 장소를
앱이 직접 표시하는 것이다. 도로·경로·안내 엔진은 기존 SDK를 사용한다. 현재 A 단계는 기존 가격 표시를 공통 계층으로 분리하고 별도 검증 앱에서 다종 샘플을
표시했다. A에서는 기본 POI 숨김이나 자체 장소 조회를 활성화하지 않았다. 현재 후보는
1.2.11/native36이며, 사용자가 A의 손가락 동작과 후속 실제 장소 표시를 확인했다. 임시 흰색 박스 디자인은
제품 UI로 채택하지 않는다. B의 전용 RPC·캐시와 C/D 연동을 검증하고 아래 §9까지 진행했다.

## 1. 첫 버전에서 제공할 범위

| 종류 | 데이터 | 표시와 선택 |
|---|---|---|
| 주유소 | 기존 Opinet 주변 조회 | 브랜드·일반휘발유 가격. 가격 미제공은 브랜드/주유소 아이콘과 상호만 표시 |
| 즐겨찾기 | 현재 계정의 등록 장소 즐겨찾기 + 일반 장소 즐겨찾기 | 즐겨찾기임을 아이콘으로 표시, 일반 장소보다 우선 |
| 집·회사 | 기존 기기 저장소 | 각각 집/회사 아이콘, 지도 범위 안의 위치만 표시 |
| 모토맵 등록 장소 | 승인되고 삭제되지 않은 장소 DB | 기존 카테고리 색과 표준 아이콘, 카테고리별 식별 가능 |
| 출발·목적·경유·내 위치 | 기존 안내 SDK/앱 | 항상 우선 보호. 자체 POI가 덮거나 중복 생성하지 않음 |

등록 카테고리는 cafe, restaurant, rest_stop, gas_station, repair_shop, viewpoint,
gear_shop, camping, car_wash다. 전국의 일반 상호·건물명 전체를 복제하는 범위가 아니다.
일반 장소를 검색해 경로 편집에서 선택하는 기존 기능은 유지한다. 일반 시설 확장은
첫 버전의 표시 품질·누락 범위 확인 후 별도 결정한다.

## 2. 현재 재사용할 부분과 필요한 보완

| 영역 | 현재 코드/제약 | 변경 책임 |
|---|---|---|
| 표시 | `KNNaviGasPriceLayer.m`: 지도 자식 UI, 좌표 투영, 연속 축소, 겹침 억제 | 가격 전용 조건을 분리하고 여러 POI 종류를 받는 표시 계층으로 확장 |
| 지도 접근·생명주기 | `KNNaviPresenter.m`: 내부 지도 연결, 안내 활성·중지·종료 | 지도 범위 이벤트와 기본 POI 표시 소유권 관리 |
| Opinet | `guideGasPriceEvents.ts`, `api/gasStations.ts` | 가격/브랜드·원본 만료 재사용. 현재 양수 가격 필터 때문에 빠지는 미제공 장소도 처리 |
| 등록 장소 | `api/places.ts`의 `nearby_places` | 카메라 범위용 얇은 조회, 반경/응답 수 제한 및 승인·삭제 조건 유지 |
| 즐겨찾기 | `api/favorites.ts` | 현재 전체 `all_places` 조회 후 ID 필터 방식을 지도 이동마다 사용하지 않음 |
| 집·회사 | `useMyPlacesStore.ts`의 기기 저장 데이터 | 서버에 목록을 올리지 않고 기기에서 범위 필터 후 네이티브 표시로 전달 |
| 선택 | `guideEvents.ts`, `guidePreview.ts`와 POI 선택 시트 | 기존 목적지/경유 선택 → 미리보기 → 확인 후 재안내 경로 재사용 |

기존 `guideEvents.ts`의 주변 장소 5개 조회/즉시 경로 변경 분기는 자체 지도 계층에 재사용하지 않는다.
닫아둔 주유소 검색·위험 제보 메뉴와 즉시 목적지 변경 API도 이 작업에서 다시 열지 않는다.

## 3. 조회·캐시 설계

- 조회 기준은 **화면에 보이는 지도 영역**이다. 카메라가 멈춘 뒤 약 600ms에 조회하고,
  이동 중 매 프레임에는 표시 위치만 바꾼다. SDK에서 화면 모서리를 좌표로 변환해 영역을
  만들고, 3D에서 유효하지 않은 모서리는 검증된 중심/축척 기반 제한 반경으로 대체한다.
- 가까운 카메라 이동은 같은 범위 캐시를 재사용한다. 화면 밖으로 약 25% 여유를 두어
  조금 움직일 때마다 새 호출이 생기지 않게 한다. 큰 이동은 새 범위 요청을 만들고 이전 요청을 취소한다.
- 등록 장소는 기존 PostGIS 조회를 사용하되 지도 전용 응답을 최대 250개로 제한하는 안으로 시작한다.
  반환 순서/상한을 명시하고, 실제 도심 데이터에서 부족하면 구역 분할·페이징을 구현한다.
  상한 도달/서버 잘림은 부분 결과로 판정하고 구역 분할·페이징 완료 여부를 별도로 관리한다.
  누락된 데이터를 모두 조회했다고 표시하지 않는다. 기기 세션 캐시의 초기 TTL 안은 5분이다.
- 즐겨찾기는 안내 진입 시 계정별로 가져오고 추가/삭제 시 즉시 무효화한다. 등록 장소 좌표는
  `favorite_places_for_map` 같은 **인증 사용자 범위의 전용 조회**를 추가하는 안으로 한다.
  서버에서 `auth.uid()`로 범위를 정하며 사용자 ID 인자를 믿지 않는다. 반환 필드는 표시용 최소 필드다.
  새 RPC가 필요하면 RLS·권한 검증과 마이그레이션을 별도 논리 단위로 준비한다.
- 집·회사는 기존 로컬 저장 동작을 유지한다. 저장 장소 목록/원본 객체를 서버 조회에 보내지 않는다.
  경로 조회와 카메라 중심 좌표 조회에 필요한 전송은 기존 동의/공급자 정책을 그대로 따른다.
- 주유소는 기존 5km 조회와 서버/기기의 **원본 fetchedAt/expiresAt**를 재사용한다.
  양수 가격은 최대 1시간, 빈 결과는 기존 5분 정책을 유지하며 수신 때 TTL을 다시 시작하지 않는다.
  부분 응답/오류의 기존 짧은 만료도 유지한다. 화면 범위 중심으로 검색할 수 있도록 현재 GPS 중심
  전용 context를 보완하되 30km 검색 메뉴 확장과 섞지 않는다. 넓은 개요 축척에서는 가격 조회를 억제한다.
- GPS 수신 대기 때문에 집·회사·즐겨찾기와 유효한 지도 범위의 장소까지 모두 지우지 않는다.
  유효한 카메라 좌표로 조회할 수 있는 상태와 새 현재 위치를 요구하는 경로 변경을 분리한다.
  초기 지도 좌표가 준비되지 않으면 검증된 출발지/기존 위치 폴백을 쓰며 0,0 등 임의 좌표로 조회하지 않는다.
- 캐시 키/응답 적용은 안내 세션, 계정, 위치 동의 revision, 공급자 범위, 지도 영역을 구분한다.
  로그아웃·계정 전환·중지·철회·안내 종료 때 표시/대기 요청/세션 캐시를 정리한다.
  오래된 영역 응답이나 철회 전 응답이 새 화면을 덮지 못하게 한다.

위 수치(600ms, 25%, 250개, 등록 장소 5분)는 구현 시작값이며, 확정 성능 수치가 아니다.

## 4. 표시·중복·터치 계약

1. 표시 우선순위는 내 위치/안내 지점 → 선택 장소 → 집·회사 → 즐겨찾기 → 주유소 가격/등록 장소다.
   내 위치와 상·하단 안내 영역은 자체 POI가 덮지 않도록 화면 좌표에서 제외한다.
2. 기존 표준 아이콘 세트와 브랜드 자산을 사용한다. 새 아이콘 도형을 직접 만들지 않는다.
   기기 배율로 한 번 렌더한 이미지/뷰를 재사용하고, 줌은 변환으로 연속 반영한다.
3. 같은 등록 ID/외부 공급자 ID는 하나로 정규화하고 집·회사·즐겨찾기 표식을 합친다.
   좌표가 가깝다는 이유만으로 다른 주유소/맞은편 업소를 같은 장소로 취급하지 않는다.
   Opinet과 등록 장소의 ID 연결이 불명확하면 가격을 임의로 옮겨 붙이지 않고 겹침을 표시 단계에서 정리한다.
4. 주유소 가격이 0/미제공이면 가짜 0원 가격을 표시하지 않는다. 기존 응답에서 얻은 브랜드/상호로
   일반 주유소 표시를 만든다. 만료 후 조회 실패 시 오래된 가격을 현재 가격처럼 보이지 않게 한다.
5. 일반 POI는 표준 카테고리 아이콘과 상호, 주유소는 브랜드/가격, 즐겨찾기는 저장 아이콘으로 구분한다.
   줌아웃하면 글자/가격을 줄이고 겹치는 라벨을 숨긴다. 선택된 장소와 내 위치는 가리지 않는다.
6. 첫 구현은 총 60개 내외의 가시 UI를 성능 예산 후보로 삼고, 가격 24개/축소 8개 제한은 유지한다.
   후보 데이터와 가시 라벨을 구분해 확대/이동 시 숨겼던 후보를 다시 표시한다. 최종 한도는 실기기 측정으로 정한다.
7. 터치 높이는 44pt 이상으로 유지하고 이웃 터치 영역이 겹치지 않도록 한다. 빈 곳 터치는 지도에 통과한다.
   가격/장소 위에서 시작한 드래그·핀치도 지도에 전달되어야 한다. 이 동작은 실제 손가락으로 검증한다.
8. 탭하면 기존 앱 소유 목적지/경유 선택 시트를 연다. 새 경로는 미리보기에서 확인한 뒤에만 적용한다.
   등록 장소 ID가 검증된 선택만 그 ID를 유지하고 일반 POI에 근처 예전 장소 ID를 상속하지 않는다.
   취소하면 원래 안내로 복귀하며 방문/주행기록의 장소 식별도 회귀 검증한다.

## 5. 연동과 기본 POI 전환

- 공통 POI 데이터 형식은 제안 단계다: `poiKey`, `kind`, 좌표, 이름, 등록/외부 ID,
  카테고리, 개인 저장 표식, 선택적 브랜드/가격과 원본 기준시각/만료를 사용한다.
- 네이티브 → JS에는 지도 영역과 요청 generation을, JS → 네이티브에는 동일 generation의
  POI snapshot을 전달하는 별도 계약/capability를 추가한다. 현재 가격 전용 bridge에 다른 장소를 억지로 끼워 넣지 않는다.
- 선택 이벤트는 안정적인 `poiKey`를 전달하고 JS가 현재 세션 catalog에서 실제 장소를 확인한다.
  기존 snapshot/token/동의 revision 검사를 거쳐 미리보기로 연결한다.
- 개발 플래그는 기본 OFF다. 자체 표시와 네이티브 수신 확인을 먼저 만든 뒤 `poiProperties.isVisible=NO`를 적용한다.
  정상 빈 결과와 조회 실패를 구분한다. 선택하지 않은 공급자 때문에 다른 자체 장소까지 막지 않는다.
- 필수 자체 데이터 준비 실패 시 기본 POI를 유지/복원한다. 두 계층을 동시에 켜 중복시키지 않으며
  해당 지도/안내 세션이 소유한 이전 표시 상태만 복원한다. Opinet 단독 실패는 다른 유효한 장소를 지우지 않는다.
- 복귀 때 유효한 snapshot은 즉시 재사용하고, 조회 중 지도/하단 바를 가리는 전체 로딩은 넣지 않는다.
- 일반 지도 화면에는 적용하지 않는다. 새 DB 조회/네이티브 계약은 검증 후 새 바이너리로 전달한다.
  현재 운영 1.2.10(61)과 로컬 1.2.11 후보의 계약·OTA를 혼합하지 않는다.

## 6. 구현 순서와 완료 조건

| 단계 | 담당 영역/순서 | 완료 조건 |
|---|---|---|
| A. 터치·표시 시제품 | 메인: 네이티브 표시/지도 연결 | 실제 손가락으로 POI 탭·드래그·핀치·3D·회전 검증. 안내 엔진과 하단 조작 유지 |
| B. 데이터 경로 | 메인: 지도 범위 조회·즐겨찾기 RPC·정규화·캐시 | 전체 장소 반복 조회 없음. 개인 자료 계정 격리, 가격 미제공·중복·빈/오류 응답 검증 |
| C. 연동 | 메인: 네이티브/JS snapshot·선택 | 이동 중 늦은 응답 차단, 장소 ID/경유 상한·취소/재안내·방문 기록 유지 |
| D. 자체 POI 전환 | 메인: 제한 플래그로 기본 POI 숨김 | 자체 표시 준비 후 전환, 실패 복원, 일반 지도 영향 없음 |
| E. 검증·전달 | verifier 검사, reviewer 검토, 메인 기기 검증 | 아래 시나리오 통과 → 최소 단위 커밋 → 사용자 지시 범위의 푸시/서버 배포/새 빌드 |

탐색은 explorer에 맡기고 설계·구현 책임은 메인에 둔다. 새로운 RPC·네이티브 기능·전체 POI
전환은 큰 변경이므로 구현 요청 후 검증·커밋하고, 푸시/DB 배포/TestFlight 전달은 별도 승인 범위로 남긴다.

## 7. 검증 시나리오

- 도시/교외/장소 없는 지역, 등록·일반 즐겨찾기, 집·회사, 가격 있음/없음, 주유소와 등록 장소 중복.
